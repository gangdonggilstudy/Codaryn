### 2.1 Anthropic 연결 방식의 변경(C-7)

- **이전 서술(단계 0)**
  - architecture.md 5절과 이 문서 M-5, O-7, O-12, 4절은 "공식 TypeScript SDK(`@anthropic-ai/sdk`)로 Messages API를 호출한다"를 전제로 했다.
- **실제 구현**
  - Node 내장 `fetch`로 직접 호출한다(`src/model/anthropic/index.ts`). SDK는 설치하지 않았고 실행 의존성이 없다.
- **근거(C-7, work-orders/phase-1b-config.md)**
  - 단계 1a의 허용 의존성 목록을 넓히지 않는다.
  - 유닛 시험에서 전송(`fetch`)과 대기(`sleep`)를 바꿔 끼울 수 있다.
  - 반복 루프는 엔진이 소유하므로(M-5) SDK의 tool runner나 자동 재시도에 기대지 않는다.
- **이 선택으로 코드가 직접 맡는 것**
  - 헤더 `x-api-key`, `anthropic-version`, 재시도·대기, 응답 크기 상한(S-10), 키 형식 검사(S-11), 오류 문구 정리(S-12), 리디렉션 거부.
- **SDK가 대신해 주던 것을 직접 하므로 남는 위험**
  - `anthropic-version` 값은 코드 상수다. 실제 호출로 확인하지 않았다.
  - `anthropic-workspace-id`는 보내지 않는다.
  - API 형식이 바뀌면 코드가 직접 따라가야 한다.
  - 이 셋은 실제 호출 점검에서 확인한다.

| GT-E1 | task가 도구 묶음을 지정한다. 엔진은 그 묶음만 모델에 제시하고 묶음 밖 호출은 `unknown_tool`로 거부한다. 설명자는 등록표에서 찾는다 | 도구 목록이 엔진에 고정돼 있다 | 워크플로마다 다른 도구 묶음 |
| GT-E2 | task의 `instructions`를 고정 시스템 문구 뒤에 붙인다(가린 뒤) | 시스템 문구가 상수다. 지시를 목표에 섞으면 기록에서 사용자 목표와 구분되지 않는다 | 워크플로별 지시 |
| GT-E3 | 계획 단계: 읽기 도구와 `propose_plan`만 제시하고, 제안이 성공하면 `needs-input`/`plan_pending`으로 끝낸다. 적용은 별도 진입점이다 | 정책 판정에 "묻기"가 없고, 실행을 멈췄다가 이어 가는 상태가 없다 | 계획 확인이 필요한 모든 워크플로 |
| GT-E4 | `completion: "human_review"`이면 자동 검증 통과 뒤 `needs-input`/`awaiting_review`로 끝낸다 | 자동 검증을 통과하면 바로 `done`이다 | 사람 확인으로 끝나는 워크플로 |
| GT-E5 | 도구 설명자의 `endsRun: "plan"` 속성으로 GT-E3을 처리한다 | 엔진이 도구 이름으로 분기하면 GT-E1의 등록표가 무의미해진다 | 엔진이 도구 이름을 모르는 상태 유지 |

- 새 도구(`propose_plan`, `inspect_files`, P1 `query_table`), 새 검증기 종류(`data_checks`, `inventory`), 적용기와 이동·폐기 되돌리기는 엔진 반복 논리가 아니라 코드 추가다. 플러그인 런타임은 두지 않는다(architecture 1절).

### 한계로 기록한 것(고치지 않음)

- **단계 2**
  - thinking 블록을 다음 요청에 보내지 않음
  - 시간 초과 뒤 POST 재전송(중복 처리 가능)
  - 키 필드 이름 목록의 빈틈
  - 4096바이트 여유보다 긴 비밀 변형의 경계 노출
  - 상태 디렉터리를 조작한 경우의 되돌리기
  - 삭제 직전의 짧은 경쟁
  - 서로 다른 실패를 번갈아 내는 경우
- **단계 3**
  - 검증 도중에만 보호 파일을 바꿨다 되돌리는 배경 프로세스
  - 시험 대상 값 자체가 시간·날짜·긴 16진수인 경우의 서명 묶임
  - 임시 이름·포트·PID 때문에 같은 실패를 못 묶는 경우
- **결정 행 안의 한계**: P-7, R-8, T-2, T-7, T-11, V-2, W-2.
- **단계 4·5 설계(결정만, 구현 뒤 시험으로 확인할 것)**
  - VS Code 확장이 넘기는 목표 문장이 명령줄 인자로 같은 사용자의 다른 프로세스에 보인다(VX-D9).
  - 실행 전 검사 중 Ctrl+C는 결과 JSON 없이 끝난다(AC-D12).
  - 자료 분석은 원자료 행을 모델로 보낸다. 가림은 등록 값만 대상이다. 그래서 개인정보 자료는 제외한다(GT-D8).
  - 폐기한 파일은 보관함에 평문으로 남고 자동 삭제가 없다(GT-D5, R-8과 같은 성격).

## 5. 확인한 외부 사실

2026-11-11 작성 과정에서 확인했고, 2026-11-12 관리자 검토에서 API 개요와 도구 실행 위치를 다시 확인했다. 실제 API 호출이나 SDK 설치로 검증한 것은 아니다.

| 사실 | 출처 | 구현과의 관계 |
| --- | --- | --- |
| Messages API는 `POST /v1/messages`, 기본 주소 `https://api.anthropic.com` | [API overview](https://platform.claude.com/docs/en/api/overview) | 구현이 그대로 쓴다 |
| 키는 `Authorization: Bearer` 또는 `x-api-key`로 보내고 `anthropic-version`이 필수 | 같은 곳 | 구현은 `x-api-key`와 고정 `anthropic-version`을 직접 넣는다(SDK 미사용) |
| 공식 TypeScript SDK는 `@anthropic-ai/sdk` | [SDKs, CLI, and libraries](https://platform.claude.com/docs/en/cli-sdks-libraries/overview) | 쓰지 않는다(C-7) |
| 클라이언트 도구는 `name`, `description`, `input_schema`로 정의하고 `tool_use`·`tool_result` 블록으로 주고받는다 | [Tool use with Claude](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) | 구현이 그대로 쓴다 |
| 서버 도구는 Anthropic 인프라에서 실행된다 | 같은 곳 | 쓰지 않는다(M-6) |
| SDK에 tool runner가 있다 | 같은 곳 | 해당 없음(M-5, C-7) |

- 작업공간에 한정되지 않은 키에는 `anthropic-workspace-id` 헤더도 필요하다는 서술이 있다([API overview](https://platform.claude.com/docs/en/api/overview)). 구현은 이 헤더를 보내지 않는다. 실제 호출 점검에서 확인한다(O-13).
- 구독 요금제와 API 과금의 관계는 확인하지 않았다. 구독을 API 키로 간주하지 않는다(M-12).
- 모델 ID, 가격, API 버전 값은 변하는 값이므로 이 문서에 고정하지 않는다.

## 6. 기록 규칙

- 확정 사항을 바꾸는 것은 사용자만 한다.
- 선택 사항은 Codex가 채택·변경한다. 위임 기간에는 임시 PM이 작업 지시서에 근거와 함께 기록하고, 이 문서는 그 요약과 연결을 유지한다. 위임이 해제되면 Codex가 이 문서를 기준으로 다시 판단한다.
- 미정 항목을 구현으로 먼저 정하지 않는다. 구현 중 필요해지면 작업 지시서의 결정으로 정하고 여기에 연결한다.
- 기존 서술과 다른 결정은 이 문서에 "이전 서술"과 "실제 구현"을 함께 적는다(예: 2.1절).
- 외부 사실을 추가할 때는 공식 문서를 실제로 열어 확인하고 링크와 확인 날짜를 적는다.
