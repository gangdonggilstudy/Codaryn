## 1. 목적과 범위

- [확정] CLI를 먼저 만들고 GUI와 VS Code 연동은 후속이다(U-2). 최종 설계까지 구현한다(CP-12 사용자 지시).
- [결정] N-13
  - VS Code 확장을 먼저 만든다.
  - 비개발자용 독립 GUI는 설계 문서까지 만들고 형태 확정은 단계 4 뒤에 한다.
  - 로컬 웹 서버 방식은 쓰지 않는다.
- [결정] 엔진은 하나이고 CLI·GUI·IDE는 어댑터다(M-2). 단계 5 완료 기준(roadmap)은 다음과 같다.
  - 어댑터가 CLI와 같은 엔진·정책·기록을 쓴다.
  - 어댑터에 작업 논리가 없다.
  - 확인 질문과 취소가 CLI와 같은 의미로 동작한다.
- 다루는 것: 대상 사용자, 화면 흐름, 형태 후보와 권고, 엔진 연결, 지원 OS, 접근성, 두 언어, 보안 경계, 검증 계획, 구현 분할안.
- 다루지 않는 것
  - VS Code 확장(P5-A), 워크플로 정의(P4-G).
  - 자기 개발 후보의 준비와 채택. 관리자 과업이므로 CLI와 VS Code에 둔다(GUI-D13).
  - 엔진 원격 실행, 계정·동기화(roadmap 단계 5 미포함), 외부 발송 도구.

## 2. 대상 사용자와 원칙

**대상**: [UX 설계](ux-design.md) 2절의 "문서 작업자(비개발자 포함)"가 주 사용자다. 이 문서는 그들에 대해 다음을 가정한다.
- 터미널, JSON, 환경 변수에 익숙하지 않다.
- 폴더 단위로 일한다.
- Git을 쓰지 않을 수 있다.

개발자는 VS Code 확장(N-13)이, 관리자는 CLI가 주 경로다.

| 과업 | GUI 화면 | CLI 대응 | 비고 |
| --- | --- | --- | --- |
| 초기 설정 | 첫 실행 안내 | `init`(N-2) | 키는 받지 않는다 |
| 모델 선택 | 설정 > 모델 | `models`(Y-1~Y-5) | 실제 API 접속 |
| 가릴 값·키 확인 | 설정 > 가릴 값, 점검 | `doctor` | 이름과 설정 여부만 |
| 작업 지정 | 새 작업 | `run`(C-8, N-8, N-9) | 프로필·워크플로 선택 |
| 계획 확인 | 계획 확인 | 단계 4 [가정] | 워크플로가 요구할 때만 |
| 실행 관찰·취소 | 실행 | 진행 줄(U-8), Ctrl+C, `--cancel-file` | |
| 결과 확인 | 결과 | `report` | |
| 되돌리기 | 결과 > 되돌리기 | `revert --dry-run`, `revert`(N-7) | 미리보기 뒤 확인 |
| 다시 실행 | 결과 | `run` | 새 실행을 만든다 |
| 실행 목록 | 홈 | `runs`, `--run latest`(N-7) | |
| 오류 복구 | 오류 카드 | stderr 사람용 오류(N-5) | |

[설계] GUI 원칙. [UX 설계](ux-design.md) 1절에 더한다.
1. **그리기만 한다.** 정책, 가림, 검증, 경로 검사, 설정 쓰기 규칙은 엔진과 CLI 공용 모듈의 함수를 부른다. GUI가 같은 검사를 따로 만들지 않는다.
2. **CLI에서 못 하는 것은 GUI에서도 못 한다.** GUI 전용 우회가 없다. 반대로 GUI가 확인 없이 권한을 넓히지도 않는다(9.2절 4).
3. **기본값은 "바꾸지 않음"·"거절"이다.** 확인 창의 기본 단추도 같다.
4. **가림본만 그린다.** 화면, 창 제목, OS 알림, 클립보드에 넣는 것 모두 같다.
5. **낱말이 먼저다.** 상태는 낱말로 구분하고 색과 아이콘은 보조로만 쓴다.

## 3. 화면 흐름

### 3.1 전체 흐름

```
[첫 실행 안내] ──(설정 파일이 이미 있음)──▶ [홈: 최근 작업 공간과 실행]
 폴더 → 모델 → 권한 → 점검                    │
                                              ├─▶ [새 작업] ─▶ [계획 확인]* ─▶ [실행] ─▶ [결과]
                                              │                                │취소     ├ 되돌리기(미리보기 → 확인)
                                              │                                ▼         ├ 다시 실행 → [새 작업](채워짐)
                                              │                          [결과: 취소됨]  └ 보고서 저장
                                              ├─▶ [실행 목록] ─▶ [결과]
                                              └─▶ [설정] 모델 · 점검 · 가릴 값 · 권한 규칙 · 프로필 · 언어
어디서든: 오류 → [오류 카드] → (고치는 화면으로 이동)
* 단계 4 워크플로가 계획 확인을 요구할 때만 [가정]
```

### 3.2 첫 실행 안내 (마법사 4쪽, `init` 대응)

1. **설정 폴더**
   - 기본 위치(N-1)를 보여 주고 만든다.
   - 설정 파일이 이미 있으면 덮어쓰지 않고 "기존 설정 사용"으로 홈에 간다(N-2).
2. **모델**
   - 키가 있으면 "Anthropic API에 접속해 목록을 가져옵니다"를 알린 뒤 목록을 받는다(Y-2).
   - 키가 없으면 자리표시자를 남기고 "키를 등록한 뒤 설정 > 모델에서 고르세요"로 넘어간다(N-2, N-3).
3. **권한**
   - 한도 기본값, 허용 명령 제안, 보호 경로 제안을 보여 준다.
   - 제안은 항목마다 체크 상자이고 기본은 꺼짐이다. 명령 인자는 고정한다(`allowExtraArgs: false`).
   - 첫 선택지로 "문서만 고칩니다(명령 실행 없음)"를 둔다. 비개발자의 흔한 경우다.
4. **점검**
   - `doctor`와 같은 항목을 낱말로 보여 준다.
   - 키가 없으면 등록 방법을 안내한다. 사용자 환경 변수에 등록한 뒤 앱을 다시 시작해야 한다(GUI-D7).
   - **키 입력란은 어느 쪽에도 없다**(C-1, N-10).

### 3.3 새 작업

```
┌ 새 작업 ─────────────────────────────────────────────┐
│ 작업 공간  [D:\work\notes            ] [폴더 선택…]   │
│   ⚠ Git 저장소가 아닙니다. 되돌리기는 이 실행이 바꾼 │
│     파일만 됩니다. 중요한 폴더면 사본에서 실행하세요.  │
│ 작업 종류  [문서 작성 ▾]   프로필 [doc ▾]             │
│ 목표       ┌──────────────────────────────────────┐ │
│            │ README에 설치 절을 추가한다            │ │
│            └──────────────────────────────────────┘ │
│ ▸ 고급(한도 · 허용 명령 · 검증)                        │
│                                  [실행  Ctrl+Enter]  │
└──────────────────────────────────────────────────────┘
```

- 작업 공간은 OS 폴더 대화상자로 고르거나 최근 목록에서 고른다.
- 폴더를 고르면 엔진 쪽 사전 검사 결과를 바로 보여 준다[가정: 5.2절 `validateWorkspace`].
  - 거부(막음): 설치 위치와 겹침(U-3), UNC·장치 경로(S-5), 설정·task 파일이 작업 공간 안(S-1).
  - 경고(막지 않음): Git 저장소가 아님. 엔진은 Git을 요구하지 않는다(M-4, [UX 설계](ux-design.md) 4.4).
- 작업 종류는 P4-G 워크플로 목록, 프로필은 N-8이다[가정].
- 목표의 키 검사(S-8)는 실행 단추를 누를 때 엔진 쪽 함수가 한다. 오류는 위치만 말한다.
- 고급은 접힌 상태가 기본이다. 이 화면에서는 한도를 내리는 것만 할 수 있다. 올리기와 명령 추가는 설정 > 권한 규칙에서 확인을 거친다(9.2절 4). 설정 한도보다 높일 수 없다(S-7).

### 3.4 실행

```
┌ 실행 중 · 작업 ux-doc · 모델 <표시 이름> ─────────────────┐
│ 상태: 실행 중   경과 0:42   턴 3/12   도구 5/24   토큰 12,400 │
├────────────────────────────────────────────────────────┤
│ 14:02:11  1턴 · 파일 읽기 README.md — 허용                │
│ 14:02:15  파일 만듦 INSTALL.md                           │
│ 14:02:16  명령 실행 — 거부: 허용 목록에 없음               │
│           (command/command_not_allowed)                  │
│ 14:02:20  검증 install-doc — 통과                         │
├────────────────────────────────────────────────────────┤
│                                         [실행 취소…]     │
└────────────────────────────────────────────────────────┘
```

- 이벤트 목록의 범위는 CLI 진행 줄(U-8)과 같다.
  - 포함: 실행 시작, 턴, 도구 허용·거부, 파일 변경, 검증, 재수정, 보호 대상 확인, 끝.
  - 모델 응답과 도구 결과는 넣지 않는다. 그것은 결과 화면의 기록 탭에서 가림본으로 본다.
- 문구는 [UX 설계](ux-design.md) 4.5의 사람 표현이고, 코드는 괄호에 둔다(N-5).
- **취소**
  - 단추를 누르면 확인 창이 뜬다: "취소해도 이미 한 변경은 남습니다. 결과 화면에서 되돌릴 수 있습니다." 기본 단추는 "계속 실행"이다.
  - 확인하면 CLI의 Ctrl+C와 같은 취소 신호를 보낸다. 끝 상태는 `cancelled`다.
  - 실수로 누르기 쉬운 단일 키(Esc)는 취소에 쓰지 않는다.
- **확인 질문**[가정: P5-A·P4-G]
  - 계획 확인과, N-11 이후의 권한 확인을 실행 화면 안의 패널로 보여 준다.
  - 질문, 선택지, 기본값은 엔진이 정한다. 기본값은 "거절"이다.
  - 모델이 만든 내용(계획 항목 등)은 "모델이 제안한 내용"으로 표시하고 글로만 그린다.
  - 기다리는 동안의 시간 한도는 계약을 따른다. 시간 한도가 있으면 남은 시간을 글로 보여 준다.
- **창 닫기·앱 종료**
  - 실행 중이면 "실행을 취소하고 닫을까요?"를 묻는다.
  - 확인하면 취소한 뒤 끝 기록(`run_finished`)을 정해진 시간 동안 기다리고 닫는다.

### 3.5 결과

| 탭 | 내용 |
| --- | --- |
| 요약 | 상태 문장([UX 설계](ux-design.md) 6절), 다음 행동 단추, 실행 id(복사 단추), 거부 모음과 허용 방법(설정 > 권한 규칙으로 이동) |
| 변경 | 파일 목록(만듦·바꿈), 비교 보기(GUI-D6), "폴더에서 보기" |
| 검증 | 검증기별 결과, 근거(가림본, 잘림 표시), 검사하지 않은 범위 |
| 보호 대상 | 무결성 확인 시점별 결과("사후 탐지"라고 쓴다) |
| 사용량 | 턴, 도구 호출, 토큰, 시간, 재수정 |
| 기록 | journal 사건 목록(가림본), 종류 필터 |

- 결과 화면은 `ReportOutput`의 구조화된 필드로 그린다. Markdown 보고서를 HTML로 바꿔 그리지 않는다(9.2절 1).
- **되돌리기**
  1. 미리보기를 보여 준다(`--dry-run` 대응, N-7). 대상 파일과 동작, 건너뛸 파일과 이유가 나온다.
  2. 확인 창의 기본 단추는 "되돌리지 않음"이다.
  3. 결과를 보여 준다: `complete` 또는 `partial`. 건너뛴 파일마다 이유를 쓰고, 이미 되돌린 실행은 그렇게 표시한다(N-7).
- **다시 실행**: 같은 설정으로 새 실행을 만든다. 이전 실행과 합치지 않는다(architecture 8절). 목표 원문의 출처는 GUI-D11이다.
- **보고서 저장**: OS 저장 대화상자로 Markdown을 저장한다. 내용은 `report`와 같은 가림본이다.

### 3.6 홈, 실행 목록, 설정, 오류

- **홈**
  - 최근 작업 공간과 각 작업 공간의 최근 실행을 보여 준다(N-7 `runs`).
  - 실행 중인 작업 공간(잠금)을 표시한다.
  - 실행 기록 정리를 두는 경우 개수와 크기를 보여 주고 확인을 받는다([UX 설계](ux-design.md) 7절, architecture A-5, privacy PV-D1).
- **설정**

| 쪽 | 내용 | 확인 |
| --- | --- | --- |
| 모델 | 목록 조회 단추(접속 고지), 현재 모델, `CODARYN_MODEL`이 덮어쓰면 그 사실(Y-3) | 고르기는 확인 없음 |
| 점검 | `doctor` 항목과 낱말 상태(ok·warn·fail·skipped) | — |
| 가릴 값 | `secretEnv` 이름과 설정 여부. 이름 추가·삭제만 하고 값 입력란은 없다([UX 설계](ux-design.md) 4.3, S-3) | 삭제는 확인 |
| 키 | 있음·없음, 등록 방법 안내. 값은 보이지 않는다 | — |
| 권한 규칙 | 허용 명령, 보호 경로, 한도 | 넓히는 변경은 OS 확인 창(9.2절 4) |
| 프로필 | N-8 프로필 목록 | 넓히는 변경은 같은 확인 |
| 언어 | 자동(OS)·한국어·English. `CODARYN_LANG`이 있으면 그것이 우선한다고 표시 | 확인 없음 |

- **오류 카드**: [UX 설계](ux-design.md) 4.9의 세 부분(무엇이, 고치는 법, 코드)을 카드로 보여 준다. 고치는 법이 화면 이동이면 그 화면으로 가는 단추를 둔다. 문구는 CLI 사람용 오류(N-5)와 같은 함수에서 받는다.

### 3.7 상태 표현

- [UX 설계](ux-design.md) 6절의 표를 그대로 쓴다. 상태 낱말(완료·실패·확인 필요·한도 도달·취소됨) 옆에 아이콘과 색을 보조로 둔다.
- 요약 탭의 다음 행동 단추는 그 표의 "다음 행동 안내" 열에서 정한다.
  - `done/verified`: 보고서 저장, 되돌리기.
  - `needs-input/protected_changed`: 보호 대상 탭으로 이동.
  - `budget-exhausted/*`: 설정 > 권한 규칙(한도), 새 작업.
  - `cancelled`: 되돌리기.

## 5. 엔진 연결 [가정: P5-A 문서 전]

### 5.1 프로세스 구성 (권고안 기준)

```
┌ 화면(렌더러) ────────────────────┐  Node 접근 없음. preload의 좁은 API만
│ HTML · CSS · JS, 글로만 그림       │
└───────────────┬────────────────┘
                │ IPC: 요청·응답과 이벤트 (네트워크 포트 없음)
┌───────────────▼────────────────┐
│ 메인: 창, OS 대화상자, 확인 창,   │  인자 검사, 경로 핸들,
│ IPC 검사, 앱 수명                │  권한 넓히기 확인
└───────────────┬────────────────┘
                │ 메시지 포트
┌───────────────▼────────────────┐
│ 엔진 호스트(Node)               │  어댑터 계약 구현을 그대로 부른다.
│ = CLI와 같은 엔진·정책·기록       │  명령은 기존 명령 실행기의 자식 프로세스
└────────────────────────────────┘
```

- 엔진 호스트를 메인과 나누는 이유(GUI-D3)
  - 엔진의 긴 동기 작업(가림, 무결성 해시 등)이 창 처리를 멈추지 않는다.
  - 엔진이 비정상 종료해도 창이 남아 안내할 수 있다.
  - Electron 실행 파일을 Node로 쓰는 기능(RunAsNode)을 켤 필요가 없다(E-4).
- 메인과 엔진 호스트 사이의 메시지는 어댑터 계약의 직렬화된 요청·이벤트를 그대로 옮긴다. 그래서 계약의 요청, 이벤트, 결과, 오류는 직렬화할 수 있어야 한다(13절).

### 5.4 GUI 전용 상태 [설계]

- 위치: 설정 디렉터리의 `gui-state.json`(N-1과 같은 디렉터리).
- 담는 것: 최근 작업 공간 경로(최대 20개), 창 크기, 마지막으로 연 탭.
- 담지 않는 것: 권한·정책·한도(설정 파일에만 둔다), 키, 가릴 값, 목표 원문(GUI-D11), 모델 응답.
- 읽지 못하거나 형식이 틀리면 버리고 빈 상태로 시작한다. 이 파일은 권한에 영향을 주지 않는다.

## 7. 접근성

[설계] 목표 수준은 WCAG 2.2 AA다. [UX 설계](ux-design.md) 8절을 GUI로 구체화한다.

| 영역 | 규칙 |
| --- | --- |
| 키보드 | 모든 동작을 키보드로 한다. 포커스 순서는 보이는 순서와 같고 포커스가 늘 보인다. 단축키: 새 작업 Ctrl+N, 실행 Ctrl+Enter, 설정 Ctrl+쉼표, 영역 이동 F6. 취소에는 단일 키를 쓰지 않는다 |
| 화면 낭독기 | 상태 전이(시작, 검증 중, 확인 질문, 끝)는 바로 알린다. 확인 질문과 끝은 끼어들어 알린다. 진행 이벤트는 몇 개씩 묶어 조용히 알린다. 이벤트 목록은 목록 구조로, 아이콘은 글 대체를 둔다 |
| 색 | 낱말이 먼저다. 글 대비 4.5:1 이상이다. OS 고대비 테마를 따르고 밝은·어두운 테마는 OS 설정을 따른다 |
| 크기 | OS 배율 100~200%와 글꼴 확대에서 잘림이 없다. 경로·실행 id는 줄바꿈하고 복사 단추를 둔다 |
| 움직임 | 애니메이션은 최소로 하고 OS의 동작 줄이기 설정을 따른다 |
| 시간 | 확인 질문에 시간 한도가 있으면 남은 시간을 글로 보여 주고 알린다[가정] |
| 언어 | 화면의 언어 속성(ko, en)을 정해 낭독기 발음이 맞게 한다 |

- 시험
  - 수동 점검표: Narrator, NVDA, 키보드만, 200% 배율, 고대비.
  - 자동 검사 도구(axe 계열 등)는 새 의존성이므로 PM 승인이 필요하다(GUI-D10).

  - N-B의 `src/i18n` 하나를 CLI와 같이 쓴다.
  - GUI 전용 문구는 같은 카탈로그에 `gui.` 접두 키로 둔다(13절, N-B 담당과 맞출 점).
  - 화면이 쓸 수 있게 카탈로그는 순수 데이터여야 한다.
- 언어 바꾸기
  - 설정 > 언어에서 바꾸면 설정 파일 `language`에 쓴다(CLI와 공유). 권한을 넓히는 변경이 아니므로 확인은 없다.
  - `CODARYN_LANG`이 있으면 그것이 이긴다는 사실을 표시한다.
- 고정하는 것: 오류 코드, 명령 이름, JSON 필드, 실행 id. 화면에서 코드는 괄호에 둔다.
- 값 넣기 금지(S-6, S-12)
  - 문구 틀에 파일·환경의 값을 넣지 않는다.
  - 사용자가 고른 작업 공간 경로는 자기 입력란에만 보이고 오류 문구에는 넣지 않는다.
- 형식
  - 날짜·시간·숫자는 지역 형식으로 쓴다. 실행 id는 UTC 원문 그대로다.
  - 영어가 더 길다. 고정 폭 단추를 쓰지 않고 줄바꿈을 허용한다.
  - 글꼴은 OS 기본을 쓰고 파일을 동봉하지 않는다.
- 모델이 만든 글(계획 항목, 검증 근거, 파일 내용)은 번역하지 않는다.

### 9.2 GUI가 새로 만드는 공격면과 대책 [설계]

1. **화면에 들어가는 신뢰할 수 없는 글**
   - 대상: 목표, 파일 이름, 검증 근거, 모델이 쓴 계획, 기록.
   - 글로만 넣는다(`textContent`). HTML로 해석하지 않는다.
   - Markdown을 HTML로 그리지 않는다. 보고서는 구조화된 `ReportOutput`에서 그린다.
   - 링크를 자동으로 만들지 않는다.
   - CSP는 앱 자원만 허용한다(`default-src 'none'`에 스크립트·스타일·이미지를 `'self'`만). 원격 자원과 `eval`이 없다.
2. **화면 격리**[E-3]
   - 문맥 격리를 켜고, 렌더러 샌드박스를 켜고, Node 통합을 끈다. `webview` 태그도 끈다.
   - 다른 주소로의 탐색과 새 창을 막는다. 권한 요청(카메라, 알림 등)은 모두 거부한다. 원격 내용을 불러오지 않는다.
3. **IPC 표면**
   - preload가 내놓는 함수는 5.2절 동작과 일대일이다.
   - 메인은 모든 인자를 스키마로 검사한다.
   - 화면은 파일 경로 문자열을 직접 넘기지 못한다. OS 대화상자나 `gui-state.json`의 최근 목록에서 메인이 발급한 **경로 핸들**만 넘긴다.
4. **권한을 넓히는 변경의 확인**
   - 대상([UX 설계](ux-design.md) 7절): 허용 명령 추가, `allowExtraArgs: true`, 한도 올리기, 보호 경로·`integrity.paths` 비우기, 가릴 값 삭제, 실행 기록 삭제.
   - 메인이 띄우는 **OS 기본 대화상자**에서 결과("이 명령은 어떤 인자든 실행합니다" 등)를 보여 주고 확인받는다. 기본 단추는 "바꾸지 않음"이다.
   - 화면이 침해되어도 확인 없이 정책을 넓히지 못하게 하기 위해서다.
5. **파일 열기**
   - 바뀐 파일을 OS 기본 처리기로 "열면" 실행 파일·스크립트가 실행될 수 있다.
   - 그래서 "폴더에서 보기"(탐색기에서 파일을 선택한 상태로 열기)만 둔다.
6. **외부 주소**: 열지 않는다. 도움말은 앱에 동봉한 문서로 보여 준다.
7. **디버그 기능**
   - 제품 빌드에서 개발자 도구, 원격 디버깅, inspect 인자, RunAsNode, `NODE_OPTIONS`를 끈다(E-4).
8. **업데이트, 충돌 보고, 원격 측정**: 기본으로 없다. 자동 업데이트는 네트워크 동작이므로 따로 정한다(GUI-D9).
9. **단일 인스턴스**: 앱은 하나만 실행되고, 두 번째 실행은 기존 창으로 간다. 동시 실행의 실제 보호는 엔진의 `lock.json`이다.
10. **엔진 호스트 비정상 종료**
    - 잠금이 남지만 다음 실행이 죽은 pid의 잠금을 회수한다(P-4). pid 재사용 오판은 남는다(architecture A-6).
    - 분리된 자식 명령은 남을 수 있다(T-2).
    - GUI는 "실행이 비정상 종료됨. 기록 확인과 되돌리기"를 안내한다.
11. **스냅샷 원문**: 스냅샷은 평문이다(R-8, PV-D1). GUI는 스냅샷 원문을 그리지 않는다. 변경 비교는 GUI-D6을 따른다.
12. **접근성 API와 OS 통합**
    - 화면 낭독기와 접근성 API는 화면의 글을 다른 프로세스에 보여 준다. 가림본만 그리므로 같은 범위다.
    - OS 알림, 점프 목록, 최근 문서 목록에는 상태 낱말과 고정 문구만 넣는다. 목표와 경로는 넣지 않는다.
