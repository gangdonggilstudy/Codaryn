# UX 설계 (CLI·GUI 공통)

- 기준: main `349726a`, 2026-11-12. 근거 검토는 [사용성 검토](usability-review.md)다.
- 상태 표기: [구현]은 main에 있는 것, [설계]는 결정만 된 것, [제안]은 이 문서의 안이다. 출력 예시는 [제안]의 문구 초안이다.
- 사용자 확정 요구: CLI 먼저·GUI와 VS Code는 후속(decisions U-2), 민감정보 가림(U-5), 편의성·UX 설계·문서화(2026-11-12 지시), "모델명을 외워 칠 수 없다"는 지적.
- PM 설계 선택: 엔진 하나와 어댑터(M-2, architecture 1절), 권한은 사용자 설정과 CLI 인자로만(M-9), 설정·키 규칙(C-1~C-8, S-1~S-12), 진행 표시(단계 3 U-8), 모델 목록(Y-1~Y-5).
- 미정: GUI 형태(O-5), VS Code 연동 방식(O-6).

## 1. 원칙

1. **엔진은 하나다.** CLI·GUI·IDE는 실행 시작, 진행 이벤트 구독, 취소, 결과·보고서·되돌리기 호출만 하는 어댑터다. 작업 논리, 권한 판단, 가림은 엔진에만 둔다.
2. **사람용 출력과 기계용 출력을 나눈다.** CLI stdout의 JSON 한 줄, 오류 코드, 종료 코드는 고정 계약이다. 사람용 문장은 stderr나 화면에 둔다.
3. **가림본만 보여 준다.** 화면, 진행 줄, 요약, 오류 문구에 비밀 값이나 키를 넣지 않는다. 파일에서 읽은 값은 오류 문구에 넣지 않는다(S-6, S-12).
4. **있는 보호만 말한다.** "통과"는 "지정한 검증 범위에서 통과"다(M-16). OS 격리가 없으므로 "안전", "샌드박스", "차단"이라고 하지 않는다(M-8).
5. **결정은 사람이 한다.** 모델 출력은 권한을 넓히지 못한다. 권한을 넓히는 동작은 사람이 확인한다(7절).
6. **다음 행동을 알려 준다.** 모든 결과와 오류는 무엇이 일어났는지, 다음에 무엇을 하면 되는지를 함께 말한다.

## 2. 대상 사용자와 주요 과업

| 사용자 | 상황 | 주요 과업 |
| --- | --- | --- |
| 개발자 | 저장소에서 작은 코딩 작업을 맡긴다 | 테스트 명령 허용, 실행 관찰, 변경 검토, 되돌리기 |
| 문서 작업자(비개발자 포함) | 폴더의 문서를 고치게 한다 | 쉬운 초기 설정, 한 줄 실행, 결과 요약, 되돌리기 |
| 관리자(PM) | 자기 개발 후보를 검토·채택한다 | 후보 준비, 보고서, 보호 대상 확인, 병합 판단 |

공통 과업: 초기 설정, 모델 선택, 비밀 등록, 작업 지정, 실행 관찰, 결과 확인, 되돌리기·재실행, 권한 거부 대처, 오류 복구.

## 3. 정보 구조

- **사용자 설정**(설정 파일, 프로필[제안], 변수 파일 경로. 항상 작업 공간 밖, S-1) → **작업 공간**(대상 폴더. 기록은 `<작업 공간>/.codaryn/`[구현]) → **작업**(목표, 권한 규칙, 검증, 한도. task 파일 또는 간편 형식[구현]).
- **실행**(실행 id, 상태와 이유, 진행 이벤트, 변경 목록, 검증 결과, 사용량, 보호 대상 확인 기록[구현]) → **동작**(보고서·되돌리기[구현], 재실행[제안]).

| CLI 명령 | 상태 | GUI 화면 |
| --- | --- | --- |
| `init` | 제안 | 첫 실행 안내 |
| `models` | 설계(Y-1~Y-5) | 설정 > 모델 |
| `doctor` | 구현 | 설정 > 점검 |
| `run` | 구현 | 새 작업 → 실행 화면 |
| `runs`, `--run latest` | 제안 | 홈(최근 실행) |
| `report` | 구현 | 결과 화면 |
| `revert` | 구현 | 결과 화면 > 되돌리기 |

## 4. 핵심 흐름

### 4.1 초기 설정 [제안: `codaryn init`]

```
$ codaryn init
설정 폴더: C:\Users\<사용자>\AppData\Roaming\Codaryn (작업 공간 밖) — 만들까요? [Y/n]
모델: 키가 없어 목록을 가져올 수 없습니다. 키를 등록한 뒤 `codaryn models --use`로 고르세요.
한도(기본값): 턴 12 · 도구 호출 24 · 토큰 150000 · 10분 — [Enter] 그대로
허용 명령 제안(작업 공간의 package.json에서): [ ] npm test  [ ] npm run build
보호 경로 제안: tests, package.json, tsconfig.json — [Enter] 그대로
키: 설정되지 않음. 사용자 환경 변수 ANTHROPIC_API_KEY로 등록하세요(값은 묻지 않습니다).
저장했습니다: ...\Codaryn\config.json   다음: codaryn doctor
```

- 키 값은 묻지 않는다(C-1). 명령 제안은 사람이 하나씩 고르고 인자는 고정한다(`allowExtraArgs: false`). 터미널이 아니면 묻지 않는다. GUI는 같은 단계를 마법사 4쪽(폴더 → 모델 → 권한 → 점검)으로 둔다.

### 4.2 모델 선택 [설계: Y-1~Y-3]

```
$ codaryn models
 #  id          이름          입력 한도   출력 한도
 1  <모델 id>   <표시 이름>   <토큰 수>   <토큰 수>   ← 현재 설정
 2  <모델 id>   <표시 이름>   <토큰 수>   <토큰 수>
$ codaryn models --use 2 --config <설정 파일>
```

- 키가 필요하고 실제 API에 접속한다(Y-2). `doctor`는 모델 존재를 확인하지 않는다는 사실을 출력에 적는다(Y-4).
- [제안] `<…>` 꼴 자리표시자는 `doctor`와 `run`이 "설정 안 됨"으로 본다.

### 4.3 비밀 등록

- [구현] 설정·task의 `secretEnv`에 환경 변수 **이름**만 적는다. API 키와 `--vars-file`이 새로 설정한 값은 자동으로 등록된다(S-2, S-4).
- [제안] `doctor`가 "가릴 값 N개: 이름 A, B — 모두 설정됨"처럼 이름과 설정 여부만 보여 준다. GUI 설정 화면에도 같은 목록을 두고 값 입력란은 두지 않는다.

### 4.4 작업 지정

- [구현] task 파일 형식과 간편 형식(`--workspace`, `--goal`, 정책·검증·한도는 설정 파일)이 있다.
- [제안] 프로필로 흔한 작업을 한 줄로 한다: `codaryn run --workspace D:\work\notes --goal "README에 설치 절을 추가한다" --profile doc`.
- GUI 새 작업 화면: 작업 공간(폴더 선택), 목표(여러 줄), 프로필, 접힌 "고급"(한도, 허용 명령, 검증). 작업 공간이 Git 저장소도 사본도 아니면 경고 한 줄을 낸다(막지 않음. 엔진은 Git을 요구하지 않는다, M-4).

### 4.5 실행 관찰

[구현] 진행 줄은 영어이고 코드가 그대로 나온다(예: `codaryn: tool run_command: denied (command/command_not_allowed)`). [제안] 문구:

```
codaryn: 실행 시작 — 작업 ux-doc, 모델 scripted
codaryn: 1턴 · 파일 읽기 README.md — 허용
codaryn: 파일 만듦 INSTALL.md
codaryn: 명령 실행 — 거부: 허용 목록에 없음 (command/command_not_allowed)
codaryn: 검증 install-doc — 통과
codaryn: 끝 — 완료: 지정한 검증 1개 통과 (done/verified)
```

- GUI: 같은 이벤트를 시간순 목록으로 보여 준다. 진행 표시와 취소 단추를 둔다. 취소는 CLI의 Ctrl+C·`--cancel-file`과 같은 신호다[구현].

### 4.6 권한 거부와 확인

- [구현] 거부된 도구 호출은 모델에 오류로 돌아가고, 기록에 권한 종류와 코드가 남는다.
- [제안] 끝 요약에 거부를 모아 보여 준다. 예: "거부 1건: 명령 실행(허용 목록에 없음). 허용하려면 설정 `policy.commands`에 규칙을 더하세요. 인자까지 고정하길 권합니다." 실행 중에 사람이 허용하는 확인 창은 두지 않는다(검토 D-5).

### 4.7 결과 확인 [제안: 끝 요약을 stderr로]

```
── 결과: 완료 (지정한 검증 1개 통과) ──
변경 1개: INSTALL.md (새로 만듦)        거부 1건 · 4턴 · 도구 2회 · 78 ms
보고서:   codaryn report --workspace D:\work\notes --run latest
되돌리기: codaryn revert --workspace D:\work\notes --run 20261111T233839Z-d9c21658
```

- GUI 결과 화면 탭: 요약, 변경(파일별 이전·이후 비교, 가림본 기준), 검증(근거, 검사하지 않은 범위), 보호 대상 확인, 사용량, 기록.

### 4.8 되돌리기·재실행

- [구현] `revert --workspace --run`. 실행 뒤 바뀐 파일은 건너뛰고 `partial`로 알린다.
- [제안] 미리보기:

```
$ codaryn revert --workspace D:\work\notes --run latest --dry-run
되돌릴 파일 1개: INSTALL.md — 삭제 (이 실행이 만든 파일)
건너뛸 파일 0개.  실행하려면 --dry-run 없이 다시 실행하세요.
```

- 재실행: GUI는 결과 화면의 "같은 작업 다시 실행"이 같은 task로 새 실행을 만든다. 이전 실행과 합치지 않는다(architecture 8절).

### 4.9 오류 복구 [제안: 사람용 오류를 stderr에]

```
codaryn: 오류 — 설정 파일이 없습니다 (invalid_config)
  고치는 법: --config <파일> 또는 CODARYN_CONFIG. 예시: examples\config.example.json
  점검: codaryn doctor
```

- 오류 문구의 형식: 무엇이(한 줄), 고치는 법(하나 또는 둘), 코드(괄호). 파일·환경 값은 넣지 않는다.
- GUI: 같은 내용을 카드로 보여 준다. 고치는 법이 화면 이동이면 그 화면으로 가는 단추를 둔다.

## 5. 용어와 문구 원칙

| 내부 | 사용자 표현(ko) | en | 원칙 |
| --- | --- | --- | --- |
| mask, privacy token | 가림, 가림 표시 | masked, placeholder | "암호화", "안전하게 보호"라고 하지 않는다. 가리는 범위와 한계를 링크한다 |
| secretEnv | 가릴 값(변수 이름) | secret variables | 값은 보여 주지 않는다 |
| policy, commands | 권한 규칙, 허용 명령 | permissions, allowed commands | 거부에는 사유와 허용 방법을 함께 쓴다 |
| protectedPaths | 보호 경로 | protected paths | "파일 도구 쓰기만 막음"을 함께 말한다 |
| verifier, pass | 검증, 통과 | check, passed | 항상 "지정한 검증 범위에서" |
| integrity check | 보호 대상 확인 | protected material check | "사후 탐지"라고 쓴다 |
| revert | 되돌리기 | revert | 건너뛴 파일과 이유를 반드시 보여 준다 |
| run, workspace, journal | 실행, 작업 공간, 실행 기록 | run, workspace, run record | 실행 id는 복사할 수 있게 한 줄에 둔다 |

## 6. 상태와 진행 표현

| 상태/이유 | 표현(ko) | 다음 행동 안내 |
| --- | --- | --- |
| done/verified | 완료: 지정한 검증 모두 통과 | 보고서, 필요하면 되돌리기 |
| failed/verifier_failed, repeated_failure | 실패: 검증 미통과(재수정 한도 소진 / 같은 실패 반복) | 보고서의 근거 확인, 목표·검증 수정 후 다시 실행 |
| failed/model_error | 실패: 모델 호출 오류(종류) | `doctor`, `models`, 잠시 뒤 다시 실행 |
| needs-input/no_verifier, verifier_inconclusive, unknown_tool_outcome | 확인 필요: 검증 없음 / 검증 판단 불가 / 결과 모르는 호출 | 검증 추가, 시간 한도 조정, 기록 확인 |
| needs-input/protected_changed | 확인 필요: 보호 대상이 바뀌어 검증 무효 | 보고서의 "보호 대상" 절, 원래대로 돌린 뒤 다시 실행 |
| budget-exhausted/* | 한도 도달: 턴·도구 호출·토큰·시간·사용량 미보고 | 한도 조정 또는 목표 나누기 |
| cancelled | 취소됨: 이미 한 변경은 남아 있음 | 되돌리기 |

- 표현은 낱말을 먼저 쓴다(완료·실패·확인 필요). 색과 기호는 보조로만 쓴다.
- 시간은 단위와 함께 쓰고, 사람용 시각은 지역 시간으로 쓴다(실행 id는 UTC).

## 7. 위험한 동작의 확인

| 동작 | 확인 방식 [제안] |
| --- | --- |
| 되돌리기 | CLI: `--dry-run` 미리보기. GUI: 목록과 확인 단추 |
| 허용 명령 추가, `allowExtraArgs: true`, 한도 올리기 | 결과("이 명령은 어떤 인자든 실행합니다")를 보여 주고 확인한다. 비대화형은 명시 플래그 없이는 바꾸지 않는다 |
| 보호 경로·`integrity.paths` 비우기 | 경고와 확인 |
| 실행 기록 삭제(`runs --prune`) | 개수와 크기를 보여 주고 확인 |
| Git도 사본도 아닌 작업 공간에서 실행 | 경고만(막지 않음) |

입력이 터미널이 아니면 묻지 않는다. 기본값은 항상 "바꾸지 않음"이다.

## 8. 접근성과 언어

- 언어: 한국어·영어 고정 문구 카탈로그(선택 규칙은 검토 D-3). 코드, JSON 필드, 명령 이름은 영어로 고정한다.
- 텍스트만으로 뜻이 통하게 한다(색 없음·`NO_COLOR`·화면 낭독기에서도 상태 낱말로 구분). 줄 너비는 100자 안팎, 경로·id는 한 줄, 진행 줄은 `codaryn:` 접두사를 유지한다. GUI는 키보드만으로 모든 동작을 할 수 있게 하고 상태 변화를 낭독기에 알린다.

## 9. GUI 형태 후보

| 후보 | 장점 | 단점·쟁점 | 엔진 연결 |
| --- | --- | --- | --- |
| VS Code 확장 | 개발자 사용처와 맞다. 편집기·비교 화면을 재사용한다. 서버가 필요 없다 | 비개발자 접근이 어렵다. 확장 API와 작업 공간 신뢰 기능은 조사하지 않았다(O-6) | 확장 호스트(Node)에서 엔진을 같은 프로세스로 부른다 |
| 데스크톱 앱 | 비개발자에게 맞다. 설치형이다 | 런타임 포함 의존성이 크다. 배포·서명·업데이트 부담이 있다 | Node 기반이면 메인 프로세스에서 같은 프로세스로 부른다 |
| 로컬 웹 UI | 브라우저만 있으면 된다. 화면 자유도가 크다 | 로컬 서버가 필요해 "서버·데몬 없음"(architecture 1절)과 충돌한다. 루프백 인증, CSRF, DNS 재바인딩 대책이 필요하고 가림본이 포트로 노출된다 | 별도 서버 프로세스 |
