## 1. 목표와 보장 범위

- [요구] 외부 LLM API로 보내기 전에 민감정보를 가역 치환하고, 로컬에서 원문으로 복원한다.
- [설계] 보장 범위는 **등록한 가릴 값의 원문과 정해진 변형(4절)의 정확 일치**뿐이다. **구현**
- 다음은 없다. 보장하지 않으며 그렇게 표시한다.
  - 최선 노력 탐지: 알려진 키 형식, 고엔트로피 문자열, 이메일 같은 패턴으로 가리는 기능. **설계만**
    - 키 모양 패턴은 가림이 아니라 다음에만 쓴다: 설정·task·`--goal` 안의 키 거부, 출력 문구 정리, 제공자 오류 문구 정리.
  - 읽기 제외 경로(모델 문맥에 넣지 않는 경로). **설계만**. `protectedPaths`는 쓰기만 막는다.
  - 임의로 인코딩·분할·변환된 비밀의 탐지, 프롬프트 주입의 완전 방어, 등록하지 않은 민감정보의 탐지.
- [설계] 가림이 실패하면 그 내용을 보내지도 기록하지도 않는다. 가림 없이 보내는 대체 경로는 없다(5절). **구현**

## 3. 가릴 값 등록(`src/cli/run.ts`, `src/cli/security/env.ts`). 구현

실행 전 단계에서 아래 순서로 모은다. 중복은 하나로 친다.

1. `secretEnv` 이름의 값(S-3)
   - task의 `privacy.secretEnv`와 설정 파일의 `secretEnv`를 합친다.
   - 이름은 `^[A-Za-z_][A-Za-z0-9_]*$`만 허용한다.
   - 값이 없거나 비면 `secret_env_missing`이다. 오류에는 위치만 적는다.
2. 키 변수의 값(S-2, SP-2, DR-34 (b))
   - 실행이 쓰는 제공자의 키(`ANTHROPIC_API_KEY` 또는 `OPENAI_API_KEY`)는 길이와 관계없이 등록한다.
   - 다른 제공자의 키 변수 값은 20자(`MIN_OTHER_PROVIDER_KEY_LENGTH`) 이상일 때만 등록한다. `x`, `EMPTY` 같은 자리표시자가 상관없는 실행의 흔한 글자를 가리지 않게 하기 위해서다. 대본 실행에서는 모든 키가 다른 제공자의 키다.
   - 확인(main `3e36b1b`, 가짜 서버): openai 실행이 작업 공간 파일을 읽어 보낼 때, 파일에 든 33자 `ANTHROPIC_API_KEY` 값은 토큰으로 갔고, `ANTHROPIC_API_KEY`를 19자 값으로 바꾸자 그 값은 그대로 갔다.
3. `--vars-file`이 새로 설정한 변수의 값(S-4)
   - 이미 환경에 있던 변수는 바뀌지 않으므로 대상이 아니다.
   - `CODARYN_CONFIG`와 제공자별 모델·주소 변수(`CODARYN_MODEL`, `CODARYN_API_BASE_URL`, `CODARYN_OPENAI_MODEL`, `CODARYN_OPENAI_API_BASE_URL`)는 제외한다.
   - 8자 미만 값도 제외한다.
   - 앞뒤 공백을 뺀 형태도 함께 등록한다.

길이 하한:
- 게이트는 빈 문자열만 거부한다.
- 변수 파일 값은 8자, 다른 제공자의 키는 20자 하한이 있다. `secretEnv` 값과 실행 제공자의 키는 하한이 없다.
- 짧은 값을 등록하면 흔한 문자열까지 가려질 수 있다.

없는 것:
- 값을 직접 등록하는 옵션, 파일 내용을 가릴 값으로 등록하기. **설계만**

키는 설정·task 파일에 두지 못한다.
- 키 필드나 현재 키 값, 키 모양 값이 있으면 `key_in_file`로 거부한다(C-1, S-6, T-14). 간편 형식의 `--goal`과 한 줄 실행의 목표도 같다(S-8).
- 현재 키 값: 두 제공자의 키 변수 중 설정된 것의 값이고, 16자(`MIN_CURRENT_KEY_LENGTH`) 이상일 때만 찾는다. 확인(main `5701ebe`): 16자 값은 거부, 15자 값은 통과했다.
- 거부하는 키 모양(DR-33, DR-36 (c), DR-40 (b))
  - Anthropic: 단어 시작의 `sk-ant-` 뒤 32자 이상이고 숫자가 든 것, 그리고 실제 키 형식(`sk-ant-` + 소문자 2~8자 + 숫자 2자 + `-` + 32자 이상)은 앞에 글자·숫자·밑줄이 붙어 있어도.
  - OpenAI: `sk-proj-`·`sk-svcacct-`·`sk-admin-` 뒤 20자 이상, 그리고 대소문자와 숫자가 섞인 긴 예전 형식.
  - 출력에서 지우는 모양(9절)은 이보다 넓다.
- 끊긴 키(DR-40 (a), DR-42 (a)(b))
  - 키 값 대조: 원문, 구분 문자(공백, 제어 문자, 서식 문자 `\p{Cf}`)를 뺀 글, 그리고 값이 '키 같은 값'이면 영문자·숫자만 남긴 글에서 비교한다(DR-43 (c)). 키 같은 값은 영문자·숫자가 16자(`MIN_KEY_SKELETON_LENGTH`) 이상이고 숫자와 대문자·소문자가 다 있거나, 32자 이상이고 숫자와 글자가 있는 값이다(`keyLikeSkeleton`). 낱말을 이은 자리표시자 같은 값은 마지막 비교를 하지 않는다.
  - 모양 검사: 원문과, 보이지 않는 문자와 줄바꿈(제어 문자, 서식 문자, U+2028·U+2029)만 뺀 글에서 한다. 보이는 공백은 남기므로 평범한 문장의 낱말이 이어 붙지 않는다.
  - 확인(main `23daf6b`, `--goal`): 등록된 값은 줄바꿈, 공백, U+200B, U+FE0F, U+034F, U+3164, `.`, 역슬래시, U+00A0으로 끊겨도 거부했고, `&#8203;` 문자 참조로 끊긴 것은 통과했다. 등록되지 않은 Anthropic 실제 형식 키는 글자 뒤에 붙거나 줄바꿈으로 끊겨도, OpenAI 접두사형 키는 U+200B로 끊겨도 거부했다. 보이는 공백으로 끊긴 OpenAI 키는 통과했다. `sk-learn`, `sk-SK`, `sk-ant-design-system` 뒤에 영어 단어와 숫자가 이어지는 목표는 통과했다.
  - 확인(main `6df2eae`, `--goal`, `ANTHROPIC_API_KEY`의 값): 키 같은 20자 값은 `.`과 U+FE0F로 끊겨도 거부했다. 키 같지 않은 16자 값(`summer2026winter`)은 영폭 공백으로 끊기면 거부했고, `.`이나 U+FE0F로 끊기면 통과했다(DR-45, 13절). `OPENAI_API_KEY`에 `not-needed-for-local-server`를 두어도 같은 낱말을 띄어 쓴 목표는 통과했다.
- 남은 빈틈: 13절.
- task·설정 파일이 1 MiB(1,048,576바이트)보다 크면 검사 전에 `invalid_task`·`invalid_config`로 거부한다. 메시지에는 파일의 내용이 없다(DR-40 (c)). 확인(main `5701ebe`): 1,048,606바이트 설정 파일과 1,048,614바이트 task 파일이 거부됐다.
- 이 검사는 JSON 해석 전 원문(`\u` 이스케이프를 푼 형태 포함)과 해석한 값 모두에 한다.

## 4. 가림(`src/privacy/index.ts`). 구현

토큰
- 형식: `PRIVACY_TOKEN_PREFIX` + 16자리 소문자 16진수 + `]]`. 정규식 `\[\[CODARYN_SECRET:[0-9a-f]{16}\]\]`(`src/contracts/text.ts`)이다.
- id: `node:crypto`의 8바이트 난수다. 값의 해시가 아니다. 충돌하면 8번까지 다시 뽑고, 그래도 겹치면 가림 실패다.
- 범위: 가림 게이트는 실행마다 하나다. 같은 실행 안에서 같은 문자열은 같은 토큰을 받는다. 다른 실행의 토큰은 이 실행에서 복원되지 않는다.

변형 목록(정확 일치, 대소문자 구분)
- 등록한 가릴 값마다 아래 형태를 모두 찾는다.
  1. 원문
  2. Base64(패딩 있음·없음)
  3. base64url(패딩 없음·있음)
  4. URL 인코딩(`encodeURIComponent`, 대문자 16진과 소문자 16진)
  5. JSON 이스케이프(따옴표 제외)
  6. 16진 표기(소문자, 대문자)
- 가릴 값에 줄바꿈이 있으면 LF만, CRLF만 쓴 형태에도 같은 목록을 적용한다.
- 목록 밖 형태는 가리지 않는다. 예: 대소문자가 섞인 16진·퍼센트 인코딩, `+` 공백, `\uXXXX`·`\/` 이스케이프, 더 큰 Base64 덩어리 중간의 가릴 값, CR만 쓴 줄바꿈, UTF-16 같은 다른 인코딩.
- **끊긴 가릴 값**(DR-40 (a), DR-42 (a)(c)): 위 목록과 별도로, 등록한 가릴 값이 구분 문자(공백, 줄바꿈, 제어 문자, 서식 문자)로 끊긴 형태도 가린다. 키 같은 값(3절)이면 그 밖의 문자(`.`, 이체 선택자 등)로 끊긴 형태도 영문자·숫자만 비교해 가린다. **구현**
  - 확인(main `6df2eae`, 대본 모델, `secretEnv`로 두 값을 등록하고 그 값이 든 작업 공간 파일을 읽음): 대문자·소문자·숫자가 섞인 20자 값은 원문, 공백·줄바꿈·영폭 공백·`.`·U+FE0F로 끊긴 형태 모두 토큰이 됐다. 키 같지 않은 값(`summer2026winter`)은 원문과 공백·줄바꿈·영폭 공백으로 끊긴 형태가 토큰이 됐고, `.`과 U+FE0F로 끊긴 형태는 그대로 기록과 모델에 갔다(DR-45, 13절).

겹침과 표지 조각
- 모든 일치 구간은 겹치거나 맞닿으면 합친다. 합친 구간 전체가 토큰 하나가 된다. 변형마다, 합친 구간마다 별도 대응표 항목이 생긴다.
- 로컬 텍스트에 이미 있는 표지 문자열(`CODARYN_SECRET`, 대소문자 무관) 조각은 그것이 이번 실행의 토큰이 아니면 그 자체를 보호 구간으로 가린다.
- 이미 발급한 토큰은 먼저 찾아 그대로 둔다. 그래서 가림을 두 번 해도 결과가 같다(`mask(mask(x)) = mask(x)`).
- 엔진의 고정 문구(시스템 문구 등)는 표지 문자열을 쓰지 않는다. 시험으로 확인한다.

## 5. 가림이 적용되는 경로. 구현

엔진(`src/engine/index.ts`)이 모델로 보내거나 기록하는 것은 모두 게이트를 지난다.

| 대상 | 처리 |
| --- | --- |
| 시스템 문구, 목표, workflow | 가린 뒤 `run_started`·첫 메시지에 |
| 모델 응답 문장, 도구 호출 인자 반향 | 가린 뒤 기록하고 다음 요청에 |
| 도구 결과 | 구조의 문자열마다 가리고, 직렬화한 JSON을 한 번 더 가린다(이미 이스케이프된 가릴 값 대비) |
| 검증기 근거·확인 항목·한계 | 가린 뒤 자른다(6절) |
| 재수정 메시지 | 기록된 근거로 만들고 다시 가린다 |
| 무결성 변경 경로 | 경로마다 가려 기록과 결과의 `protectedChanged`에 넣는다 |
| journal, result.json | 가림본 필드만 받는다(`src/store`) |
| 진행 표시(stderr) | 가림본 기록으로 만든다(U-8) |
| 에이전트의 마지막 답(DR-47, 결과의 `finalMessage`와 끝 요약) | 기록된 모델 응답 문장(가린 것)에서 만든다. 키 모양은 `[key]`로 바꾸고, 제어 문자와 보이지 않는 문자는 빼고(줄바꿈은 LF, 탭은 남김), 2,000자(코드 포인트)까지 자른다. 토큰이나 `[key]` 가운데서는 자르지 않는다. 머리말이 에이전트의 말이며 검증된 사실이 아니라고 말한다. 같은 글이 `report`(Markdown 절과 `--json`의 `result.finalMessage`)와 GUI의 결과·보고서 화면에 나온다. **journal에는 모델 원문이 남는다:** `model_response.text`는 턴마다 모델이 보낸 글이며, 등록한 가릴 값만 토큰이고 이 처리(키 모양, 제어 문자, 길이)를 거치지 않는다(키 모양은 가림 대상이 아니다, 1절). 마지막이 아닌 답도 남는다(main `a191a50`의 3절 체험에서 확인, [사용 안내](usage.md) 8절) |
| 계획의 요약(U-14, `plan`의 "에이전트의 설명"과 `--json`의 `summary`) | 계획 실행 journal에 기록된 `propose_plan` 인자(가린 것)에서 읽어, 지금 명령이 등록한 가릴 값으로 다시 가리고, 키 모양과 지금 키는 숨기고, 제어 문자는 뺀다. 제안 때 500자까지다. 다이제스트에 들지 않으므로 승인 대상이 아니라고 머리말이 말한다. 기록 변경 표시가 있는 계획 실행이면 보이지 않는다(그 journal도 바뀌었을 수 있어서) |
| CLI 조립 오류 문구 | 등록한 가릴 값을 `[secret]`으로 바꾼다 |

`search_files`는 가림본 경로와 가림본 파일 내용에서만 찾는다. 원문으로 찾으면 결과의 유무로 가릴 값을 한 글자씩 알아낼 수 있기 때문이다.

가림 실패
- 엔진: 그 내용을 보내지도 기록하지도 않고 실행을 `failed`/`model_error`로 끝낸다.
  - 예외: 모델 오류 문구와 무결성 알림은 가리지 못하면 버리고 계속한다.
- 도구(`search_files`, `write_file`, `run_command`): 그 호출만 `masking_failed`로 실패하고 실행은 계속된다.
- 가림에는 시간 제한이 없다. 동기 계산이다.

가림 개수(DR-52, U-25). **구현**
- 실행의 결과(`run`의 stdout JSON과 `result.json`)에 `masking: {registeredValues, maskedPlaces}`가 실린다. 둘 다 정수다. `report --json`의 `result`에도 같은 값이 있고, 사람용 끝 요약에 한 줄로 나온다(사용 안내 8절 "가림 개수"). 값, 위치, 길이, 해시는 싣지 않는다.
- 없는 곳: journal(`run_finished` 포함), `report`의 Markdown 본문, 진행 줄. 모델은 개수를 볼 수 없다. 개수는 실행 끝에 결과를 지을 때만 넣는다(`src/engine/index.ts`). GUI 화면도 이 개수를 보이지 않는다(코드 확인. GUI는 띄우지 않았다).
- `registeredValues`: 3절로 모은 서로 다른 값의 수다. 가림 게이트가 줄바꿈의 CRLF를 LF로 바꾸어 같은 값을 하나로 센다. 3절이 이미 같은 값을 하나로 치므로 출처가 달라도 하나다. 변수 파일 값의 공백을 뺀 형태는 3절에서 따로 등록되므로 따로 센다. 등록한 값이 없으면 필드가 없다.

  - 겹치거나 맞닿은 구간은 토큰 하나가 되므로(4절) 한 곳으로 센다.

- 알리는 것과 한계: 13절(사용자 결정 DR-54, 보안 검토 R-57 L-1~L-3).

## 6. 가린 뒤 자르기. 구현

원문을 먼저 자르면 가릴 값이 반으로 갈려 가림이 알아보지 못한다. 그래서 넉넉히 받아 가린 뒤 자른다.

- **명령 출력**(`src/tools/command-runner.ts`, `src/tools/index.ts`)
  - 스트림마다 65,536바이트에 여유 4,096바이트를 더 받는다. 그보다 많으면 버리고 `truncated`를 표시한다.
  - `run_command` 결과는 전체를 가린 뒤 가림본 65,536바이트로 자른다. 토큰이나 서로게이트 쌍 가운데서는 자르지 않는다.
  - `truncated`이면 "원문 앞 65,536바이트를 가린 결과"와 공통인 앞부분만 남긴다. 앞의 긴 가릴 값 때문에 가림본이 짧아져도 가릴 값의 끊긴 조각이 남지 않게 하기 위해서다.
- **끝까지 읽지 못한 출력**(V-2, 수정된 규칙)
  - 대상: 종료 뒤 유예 만료, 시간 한도, 취소로 끝난 스트림이 상한 초과 없이 끊긴 경우.
  - 처리: 마지막 LF 뒤의 불완전한 줄(최대 4,096바이트)을 버린다.
  - 등록한 가릴 값이 잘린 지점에 걸쳐 있으면 그 값의 시작 앞까지 자른다. 탐색 범위는 16,384 단위다.
  - 취소된 `run_command`는 출력을 돌려주지 않는다.
- **검증 근거**(T-6)
  - 검증기는 원문을 자르지 않는다. 실행기가 잘랐으면 `evidenceTruncated`를 표시하고, 잘렸을 수 있는 스트림을 맨 뒤에 둔다.
  - 엔진은 가린 뒤, 잘린 근거면 끝 4,096바이트를 토큰 경계에 맞춰 버리고 고정 안내 문구를 붙인다.
  - 그다음 `MAX_EVIDENCE_BYTES`(8,192)로 앞뒤를 남기고 가운데를 생략한다.
- **검색 결과 줄**: 1,000자에서 토큰 경계에 맞춰 자르고 `truncated`를 표시한다.

## 7. 복원과 문서 변경(원위치 규칙). 구현

**필드 복원**(`resolveToolArgs`)
- 도구가 선언한 복원 허용 필드만 대상이다. 정책이 `restorePathTokens: true`일 때만 복원한다(기본 false). 그 필드는 `read_file.path`, `search_files.path`, `write_file.path`, `run_command.cwd`다.
  - 그 필드의 토큰은 원래 문자열로 바꾼다.
  - 변형 토큰이면 그 변형 문자열로 바꾼다.
- 그 밖의 필드에 토큰이 있으면 `unresolved_token`이다. 객체 키에 든 토큰도 같다. 명령 실행 파일, 명령 인자, 환경은 어떤 경우에도 복원하지 않는다.
- 발급하지 않은 토큰, 모양이 바뀐 토큰, 모델이 보낸 표지 조각은 `invalid_token`이다. 오류에는 필드 경로만 적는다.
- 엔진 순서
  1. 형식 검사
  2. 정책 1차(토큰이 든 인자)
  3. 복원
  4. 형식 재검사
  5. 정책 2차(실효 인자, 경로에 남은 조각은 거부)
  6. 실행
  7. 결과 가림
  8. 기록
- 복원 거부는 `restore` 단계로 기록한다.
- 가릴 값별·목적지별 복원 권한은 없다. 경로·cwd 외의 복원은 하지 않는다. **새 위치 복원 권한은 설계만**

**문서 변경**(`write_file`, `rebuildDocument`)
1. 현재 해시가 `expectedHash`와 다르면 `conflict`로 쓰지 않는다. 새 파일은 `expectedHash: null`이다.
2. `replace_text`는 가림본(BOM 제외)에서 `oldText`가 정확히 한 번 나와야 한다. 아니면 `no_match`나 `ambiguous_match`다.
3. 모델이 준 새 가림본에 발급하지 않은 표지 조각이 있으면 `invalid_token`이다.
4. 원래 가림본과 새 가림본을 LF로 나눈다. **토큰이 든 줄(보호 줄, CR 포함)은 내용과 순서가 그대로여야 한다.** 다르면 `protected_span_violation`이다. 토큰이 없는 줄은 자유롭게 더하고, 지우고, 바꿀 수 있다.
5. 토큰은 값을 찾아서가 아니라 보호 줄의 위치로 원문을 되살린다. 그래서 토큰을 다른 위치나 다른 파일로 옮기거나 복사할 수 없다. 토큰이 든 새 파일은 거부한다.
6. 예외가 나면 거부로 처리한다(fail closed). 쓰기 전에 원문 스냅샷을 저장하고(저장 실패 시 쓰지 않음), 원자적으로 쓰며 해시를 다시 확인한다.

이 규칙은 단계 0 설계의 "구간 대응"보다 엄격하다(줄 단위). 가릴 값이 든 줄의 다른 부분도 모델은 고칠 수 없다.

## 8. 대응표, 기록, 스냅샷

- **대응표**: 가림 게이트 안의 메모리 두 개뿐이다. 실행이 끝나면 사라지고 디스크에 쓰지 않는다. 금고, 영구 저장, 암호화는 없다. **구현**
  - 실행이 끝난 뒤의 기록과 결과에 남은 토큰은 원문으로 되돌릴 수 없다.
  - 영구 금고(OS 자격 증명 보호 등)는 **설계만**이며 도입 여부는 [미정].
- **journal, result.json**: 가림본만 담는다. 위치는 `<작업 공간>/.codaryn/runs/<runId>/`다. **구현**
  - 가림본이라는 것은 등록한 가릴 값이 토큰으로 바뀌었다는 뜻이다. journal의 모델 응답 글(`model_response.text`)은 그 밖의 처리 없이 남는다: 등록하지 않은 키 모양과 제어 문자가 그대로이고, Codaryn이 길이를 자르지 않는다. 사람에게 보이는 마지막 답(`finalMessage`)과 계획의 요약만 5절의 처리를 더 거친다. journal을 남에게 줄 때는 이 점을 생각한다.
- **상태 디렉터리의 변경 감지**(DR-38): 실행의 시작과 끝, 명령을 돌린 뒤마다 `.codaryn/`을 살펴, 그 실행이 쓴 것 말고 바뀐 것이 있으면 실행을 `failed`/`state_changed`로 끝내고 그 실행에 기록이 바뀐 표시를 남긴다. 표시가 있는 실행은 `changes`가 글을 보이지 않고, `report`가 그렇다고 알린다. 표시가 있는 계획 실행은 `apply`가 묻기 전에 `plan_records_changed`로 거부하고 아무것도 옮기지 않는다(U-1, main `a7f3a2f`에서 확인). 실행이 끝난 뒤의 변경은 알아채지 못한다(13절). **구현**(main `6df2eae`: 허용한 명령이 실행 자신의 기록, 끝난 다른 실행의 `result.json`, `.codaryn/`의 새 파일을 고친 세 경우 모두 확인)
- **스냅샷**(R-6, R-8, T-11)
  - 위치는 `<작업 공간>/.codaryn/runs/<runId>/snapshots/`다. `index.json`(원래 상대 경로)과 `<n>.orig`(BOM 포함 원문 바이트)가 있다.
  - 변경 보기용 기록 `shown-<n>.json`(DR-29, DR-32 (c)): 쓰기 도구가 남긴다. 파일의 SHA-256과, 실행 때 가린 표기의 다이제스트만 담는다. 가린 조각이나 가릴 값은 없다(main `3e36b1b`에서 가릴 값이 든 파일을 쓴 실행의 기록으로 확인). `changes`는 지금 가릴 값으로 다시 가린 결과가 이 다이제스트와 같을 때만 가린 글을 보인다. 이 기록을 고쳐 넣으면 그 확인을 속일 수 있다(13절).
  - 보호 수준
    - 평문이며, 별도 권한 설정과 암호화가 없다.
    - 자동 삭제가 없다.
    - 파일 도구는 상태 디렉터리에 닿지 못한다. 그러나 **허용된 명령은 사용자 권한으로 읽을 수 있다.**
    - 사용이 끝난 실행 디렉터리는 사용자가 지운다.
  - **구현**
- **Git**: 상태 디렉터리에는 `*` 한 줄짜리 `.gitignore`를 만든다. 이미 있으면 덮어쓰지 않는다. **구현**
- **되돌리기**: `codaryn revert`가 스냅샷 원문을 원위치에 다시 쓴다. 현재 해시가 그 실행의 결과와 같은 파일만 대상이다. 출력에는 비밀을 넣지 않는다. **구현**

## 9. API 키

- [요구] 첫 제공자는 Anthropic이다. 두 번째 제공자 OpenAI가 더해졌다(DR-22, DR-31). 키는 제공자마다 로컬 환경 변수 하나로만 받는다: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`(`--vars-file`로 적재 가능). **구현**
- 실행 하나는 제공자 하나만 쓴다. 키는 그 제공자의 요청 헤더에만 넣는다: Anthropic은 `x-api-key`, OpenAI는 `Authorization: Bearer`. 모델 문맥, 기록, 결과, 자식 환경(허용 목록에 없음)에 넣지 않는다. **구현**
  - Anthropic: 가짜 서버 통합 `m01`로 확인했다.
  - OpenAI: main `3e36b1b`에서 가짜 서버가 받은 요청 모두 `Authorization`에만 가짜 키가 있었고, 본문에는 없었으며, `x-api-key` 헤더는 없었다.
- 한 제공자의 키는 그 제공자의 주소로만 간다. 주소 변수도 제공자별이다(`CODARYN_API_BASE_URL`, `CODARYN_OPENAI_API_BASE_URL`, DR-34). 주소는 `https`만 받고 `http`는 루프백만 받는다. 리디렉션은 따르지 않는다.
- 가릴 값으로 자동 등록한다(3절). 파일이나 명령 출력에 같은 값이 나오면 가려진다.
- 출력 가능한 ASCII가 아니면 보내지 않는다(S-11). 이 검사는 전송 직전 제공자 안에서 한다.
- 오류 문구에서 키 전체, 8자 이상 키 조각, 키 모양 문자열을 지우고 300자로 자른다(S-12). 전송 계층 오류는 고정 문구로 바꾼다.
  - 두 제공자 모두 401·403은 제공자의 문구와 오류 종류 코드를 옮기지 않고 고정 문구와 요청 id만 남긴다(OpenAI DR-35 (a), Anthropic DR-37 (a)). 제공자가 키의 앞부분과 끝 4자를 되비추면, 8자 미만의 끝 조각은 위 규칙으로 지워지지 않기 때문이다.
    - 확인(OpenAI, main `3e36b1b`, 가짜 서버): 기록의 `model_error`는 `HTTP 401: the key or its access was refused; the provider's message is not shown (request req_fake_1)`이고, 출력과 기록 어디에도 키의 끝 4자가 없었다.
    - 확인(Anthropic, main `5701ebe`, 127.0.0.1의 가짜 서버): 401과 403 모두 기록의 `model_error`가 `auth_failed`이고 같은 고정 문구(`HTTP 401: …`, `HTTP 403: …`)와 요청 id였다.
  - OpenAI의 오류 본문은 할당량 소진을 가려내려고 64 KiB까지 읽는다(DR-35 (b)). 문구는 같은 규칙으로 300자까지다. Anthropic은 4,096바이트까지 읽는다.
- `doctor`는 키의 유무만 보이고 값은 출력하지 않는다(U-6).
- `models`는 고른 제공자 하나에만 목록을 요청한다. 목록의 id에 키 값, 8자 이상 키 조각, 키 모양이 있으면 그 목록을 쓰지 않는다.

## 10. OpenAI 제공자: 응답 저장과 추론 항목

OpenAI의 Responses API(`POST /v1/responses`)를 쓴다. Anthropic과 다른 점은 대화를 이어 가는 방식이다.

- **응답 저장 끔**: 요청마다 `store: false`를 보낸다. 생략하면 OpenAI가 응답을 30일 저장한다(사실 C-11). **구현**(main `3e36b1b`, 가짜 서버가 받은 모든 요청)
- **추론 항목**: 저장하지 않으므로 다음 요청에 앞 응답의 `output` 항목을 모두, 추론 항목(`type: "reasoning"`의 `encrypted_content`)까지 다시 보내야 한다(C-11). **구현**(가짜 서버: 둘째 요청의 입력이 `message`, `reasoning`, `function_call`, `function_call_output` 순이었다)
  - 추론 항목은 OpenAI가 암호화한 것이라 **가림 게이트가 그 안을 볼 수 없다.** 가리지도 검사하지도 않는다.
  - 그 항목은 실행 중 메모리에만 두고, **같은 실행 안에서 같은 제공자에게만** 다시 보낸다. 실행이 끝나면 버린다. 디스크에 쓰지 않고, 새 실행은 앞 실행의 항목을 보내지 않는다.
  - 다시 보낼 항목은 16 MiB(`MAX_KEPT_OUTPUT_BYTES`)까지다. 넘으면 다음 요청을 보내지 않고 실행을 오류로 끝낸다(DR-35 (d)).
- **되돌려 보내는 항목은 가림 게이트를 지나지 않는다**: 앞 응답의 항목(모델 문장, 도구 호출 인자 포함)은 제공자가 보낸 그대로 다시 간다. 모델이 스스로 등록된 가릴 값을 문장에 쓰면 그 값이 같은 제공자에게 그대로 다시 간다. 이미 제공자가 낸 값이므로 새로 알리는 것은 없다. 로컬의 원문이 이 길로 나가지는 않는다: 도구 결과와 파일 내용은 여전히 가린 뒤 보낸다(5절). Anthropic 경로는 엔진이 가린 문장을 다시 보낸다는 점이 다르다.
- **기록에는 개수만**: 실행 기록에는 응답마다 추론 항목의 개수만 남는다(`model_response`의 `reasoningItems`, 없으면 필드 없음). 내용은 기록, 결과, 이벤트, 보고서에 없다. **구현**(main `3e36b1b`: 가짜 서버로 실행한 기록에 개수 1이 있고 암호문과 키는 없었다)
- **호출 id**: 제공자의 `call_id`가 안전한 id 규칙(AC-D15)을 통과하면 Anthropic처럼 그대로 기록한다(DR-35 (c)). 통과하지 못하면 기록에는 `codaryn-call-<n>`을 쓰고 원래 id는 메모리에만 둔다.
- **OpenAI 쪽 보존**(사실 C-14): API로 보낸 자료는 기본으로 학습에 쓰이지 않는다. 남용 감시 기록은 최대 30일 보존된다. 보존 없음(ZDR)은 OpenAI의 사전 승인이 필요하다. 응답 저장(C-11)과 남용 감시 기록(C-14)은 사실 문서에 따로 적힌 항목이고, Codaryn이 끄는 것은 응답 저장뿐이다.

## 11. 자식 프로세스와 실행 격리

- 자식 환경
  - 허용 목록 11개 이름(PATH, PATHEXT, SYSTEMROOT, WINDIR, COMSPEC, TEMP, TMP, TMPDIR, HOME, USERPROFILE, LANG)만 넘긴다.
  - 그 값에 등록된 가릴 값이 들어 있으면 그 변수도 뺀다(T-1). **구현**
  - Windows에서 libuv가 스스로 넣는 변수(USERNAME 등)는 이 검사를 거치지 않는다.
- 명령은 허용 규칙(실행 파일, 인자 접두사)으로만 실행한다. 대화형 승인은 없다. 작업 디렉터리는 허용 루트 안이다.
- 이 조치는 OS 수준 강제가 아니다. [설계] 그래서 "네트워크 차단"이나 "파일 접근 차단"이라고 부르지 않는다. OS 격리 실행기는 [미정].
  - 실행된 명령(검증기 포함)은 디스크의 원문(스냅샷, 작업 공간 밖 파일)을 읽을 수 있다.
  - 비밀을 변환해 출력하거나 네트워크로 보낼 수 있다.
  - 모델이 쓴 코드가 검증기로 실행되는 경우도 같다(T-7).
- 셸, 확장, MCP의 실행 권한을 모델 출력이나 프로젝트 문서가 넓힐 수 없다. MCP와 확장은 없다.

## 12. 형식별 지원

| 형식 | 처리 |
| --- | --- |
| UTF-8 텍스트 파일과 파일 경로 | 지원. 등록 값을 가리고 7절의 원위치 규칙을 적용한다. **구현** |
| NUL 바이트나 잘못된 UTF-8이 든 파일 | 파일 도구가 `not_text`로 읽지 않는다. `search_files`는 그런 파일을 결과 없이 건너뛴다. **구현** |
| 텍스트 기반 표와 데이터(CSV, JSON) | 텍스트로 다룬다. 숫자 값의 치환, 자료형 보존은 없다 |
| 구조가 있는 문서(워드프로세서, 스프레드시트, PDF) | 미지원. **설계만**: 모델 전송과 가림 상태의 수정을 하지 않는다 |
| 이미지와 스크린샷 | 미지원. 이미지를 보내는 도구가 없다. **설계만**: 로컬 가림 처리기 전에는 전송 차단 |

외부로 나가는 경로는 실행마다 고른 제공자(Anthropic 또는 OpenAI) 하나의 요청뿐이다. `models`는 고른 제공자 하나에 모델 목록을 요청한다. OpenAI 요청에는 되돌려 보내는 응답 항목이 들어가며, 그것은 게이트를 지나지 않는다(10절). 다음은 그 기능이 생길 때 같은 게이트를 지나야 한다는 설계다. **설계만**
- MCP, 임베딩, 문맥 요약, 사용량 보고
- 재시도(재시도는 이미 구현되어 있으며 처음 만든 가림 요청 본문을 그대로 다시 보낸다)

## 13. 알려진 한계

- 등록하지 않은 비밀, 목록 밖 변형, 다른 인코딩(UTF-16LE, CP949 등)은 가려지지 않는다.
- 끊긴 가릴 값의 보장은 여유 구간(4,096바이트) 이하의 형태까지다. 16진 표기처럼 원문의 두 배가 되는 긴 변형이 경계에 걸리면 앞부분이 남을 수 있다.
- 줄바꿈 뒤에서 끊긴 여러 줄로 된 가릴 값은 앞 줄이 남을 수 있다(V-2).
- 실행된 명령과 모델이 쓴 코드는 원문을 읽고 변환해 내보낼 수 있다. OS 격리가 없다.
- 파일 해시가 모델과 기록에 노출된다(P-7). 짧거나 추측 가능한 내용은 해시로 확인될 수 있다.
- **가림 개수가 알리는 것(사용자 결정 DR-54, 보안 검토 R-57 L-1~L-3, 5절 "가림 개수"):** 개수만 싣지만 아래를 알린다.
  - **등록 값 전체와 같은 글이 모델에 갔는지(L-1):** 가린 곳의 수는 모델이 받은 글에 등록 값 전체(또는 4절의 목록 변형, 끊긴 형태)와 같은 글이 있었는지를 알린다.
    - 작업 공간에 글을 넣을 수 있고 실행의 출력(stdout JSON, 끝 요약, `report --json`)도 보는 사람은 짧은 값(PIN, 짧은 암호)의 추측이 맞는지 확인할 수 있다. 한 파일에 추측을 여럿 넣으면 맞은 수만큼 늘어서, 나눠 가며 여러 번 돌리면 어느 추측이 맞았는지도 가려낼 수 있다.
    - 값의 일부만 맞으면 개수는 바뀌지 않는다. 그래서 한 글자씩 맞혀 가는 길은 없고, 키처럼 긴 무작위 값에는 쓸 수 없다.
    - 같은 사실은 journal의 도구 결과에 남은 토큰 자리에 이미 있고, 그쪽은 위치까지 알린다. 모델도 받은 글에서 토큰 자리를 본다. 새로운 점은 이 사실이 journal 없이 stdout과 끝 요약에도 나온다는 것이다. 정직한 모델로 돌린 실행도 그렇다.
    - **짧은 비밀을 가릴 값으로 쓰는 실행의 출력은 공개 로그(공개 CI 로그 등)에 남기지 않는다.**
  - **표지 글도 가린 곳으로 센다(L-2):** 표지 조각(`CODARYN_SECRET`, 대소문자 무관, 4절)이 든 글을 모델이 읽으면 그 조각을 가린 토큰도 센다. 등록 값이 어디에도 없어도 개수가 는다. 그래서 가린 곳의 수는 등록 값이 나온 횟수가 아니다.
    - 값이 새지는 않는다. 가린 값은 늘 토큰이 되어 세어지므로, 개수를 줄여 진짜 가림을 숨기는 길도 없다.
    - 모델이 스스로 늘리지는 못한다. 토큰 모양을 `write_file`로 쓰려 하면 `invalid_token`으로 거부된다(R-57에서 확인). 늘리는 길은 작업 공간에 이미 있는 글이나 허용한 명령의 출력뿐이다.
    - DR-54는 이 성질을 문서에 적기로 했다. 세는 방법은 바꾸지 않았다.
  - **등록 개수에 드는 것(L-3):** 3절의 값이 모두 든다(`secretEnv`, 실행 제공자의 키, 20자 이상인 다른 제공자의 키 변수, 변수 파일 값). 같은 값은 하나로 센다. 그래서 출력을 보는 사람은 그 환경에 실행 설정에 없는 다른 제공자의 키 변수가 있는지, 설정한 두 값이 같은지를 알 수 있다. 값과 길이는 알리지 않는다.
  - **0은 보증이 아니다:** 목록 밖 변형과 DR-45의 끊긴 값은 가려지지 않으므로 세지도 않는다.
- 가릴 값이 든 줄은 모델이 고칠 수 없다. 대응표 표지 문자열이 든 파일(Codaryn 자기 소스 일부)도 그 줄을 고칠 수 없다(decisions.md O-14).
- 실행이 끝나면 대응표가 사라져 기록의 토큰을 원문으로 되돌릴 수 없다.
- 스냅샷은 평문으로 남고 자동 삭제되지 않는다.
- OpenAI의 추론 항목은 암호문이라 가리거나 검사할 수 없다. 되돌려 보내는 응답 항목은 제공자가 보낸 그대로라 게이트를 지나지 않는다(10절).
- OpenAI 쪽에는 남용 감시 기록이 최대 30일 남는다(C-14). Codaryn이 끄는 것은 응답 저장(`store: false`)뿐이다.
- 끊긴 가릴 값의 거부와 가림에 남은 빈틈(확인은 main `6df2eae`, 3절·4절):
  - **키 같지 않은 등록 값이 드문 문자로 끊긴 경우(사용자 결정 DR-45)**: 짧거나 한 가지 대소문자만 쓴 값이 `.`이나 이체 선택자 같은 구분 문자가 아닌 문자로 끊기면 거부도 가림도 되지 않는다. 모든 등록 값에 영문자·숫자 비교를 하면 평범한 글의 오탐이 늘어서 알려진 한계로 둔다. 가릴 값이 그런 값이면, 그 값이 이상한 문자로 끊겨 들어 있을 수 있는 파일은 작업 공간에 두지 않는다.
  - 찾지 못하는 끊김: 등록되지 않은 키가 보이는 공백으로 끊긴 경우(DR-42 (b)가 보이는 공백을 남긴 대가), 등록된 키가 `&#8203;` 같은 문자 참조로 끊긴 경우.
- 실행 기록 변조(DR-37 (b), DR-38): 상태 디렉터리는 모델의 파일 도구로는 쓸 수 없지만, 허용한 명령과 같은 사용자의 다른 프로그램은 쓸 수 있다. 실행 중의 변경은 알아채지만(8절), **실행이 끝난 뒤의 변경은 알아채지 못한다.** 실행이 남긴 자식 프로세스나 다른 프로그램이 끝난 실행의 변경 보기 기록(`shown-<n>.json`) 다이제스트를 지금 값으로 바꿔 넣으면, `changes`를 다른 가릴 값으로 볼 때 실행 때 가렸던 값이 그대로 보인다. 드러나는 값은 작업 공간 파일에 이미 있는 값이다. `report`도 같은 이유로 기록만큼만 믿을 수 있다. 끝난 실행의 스냅숏을 고친 경우는 `revert`가 다이제스트로 알아채고 그 파일을 건너뛰었다(확인, main `6df2eae`).
- 실제 Anthropic API와 실제 OpenAI API로는 확인하지 않았다.

## 14. 미정과 결정 필요

[미정]
- 최선 노력 탐지(개인정보, 사내 식별자 포함 여부)
- 영구 금고
- 새 위치 복원 권한의 형식과 부여 절차
- 이미지 가림 처리기
- OS별 격리 실행기
- 로컬 모델 사용 시 치환 적용 여부
- 숫자·표의 보존 치환
- 구조가 있는 문서 형식의 지원 순서

| 번호 | 선택지 | 권고 |
| --- | --- | --- |
| PV-D1 | 스냅샷 보호(평문, 명령이 읽을 수 있음) | OS 격리 전에는 실행 디렉터리 정리를 사용자 절차로 두고, report에 스냅샷 위치와 "평문" 안내를 넣는다. 암호화는 키 보관 문제가 생기므로 격리 설계와 함께 정한다 |
| PV-D2 | 짧은 `secretEnv` 값(하한 없음) | 변수 파일처럼 8자 하한을 두거나, 짧은 값을 등록하면 doctor가 경고한다. 권고: doctor 경고(기존 동작 유지) |
| PV-D3 | 목록 밖 변형(대소문자 섞인 16진·퍼센트, `\uXXXX`) | 실제 누출 사례가 확인되기 전에는 늘리지 않는다. 늘리면 오탐과 성능을 함께 시험한다 |
