# 민감정보 처리

담당 페르소나: 보안·개인정보 검토자(주), 검증 엔지니어(보조).

현재는 코드가 없는 설계 단계다. 이 문서의 모든 항목은 설계이며 구현되거나 검증된 것은 없다. 검증 방법은 [테스트 전략](testing.md)에 둔다.

표기는 다음과 같다.

- **[요구]** 사용자가 확정한 요구.
- **[설계]** Codex가 검토해 채택한 설계 선택. 구현 단계에서 정할 세부는 [미정]으로 표시한다.
- **[미정]** 아직 결정하지 않은 항목.

## 1. 목표와 보장 범위

- [요구] 외부 LLM API로 보내기 전에 민감정보를 가역 치환하고, 응답은 로컬에서 원문으로 복원한다.
- [설계] 보호 대상은 종류에 따라 보장 수준이 다르다.

| 구분 | 대상 | 보장 수준 |
| --- | --- | --- |
| 등록한 비밀 | 사용자가 등록한 값, 지정한 환경변수와 비밀 파일의 값 | 원문과 정해진 변형 목록(§3)에 대해 정확 일치로 치환한다. 이 계층만 검증 대상 보장으로 표현한다. |
| 최선 노력 탐지 | 알려진 키 형식, 고엔트로피 문자열, 이메일 등 패턴 | 놓치거나 잘못 잡을 수 있다. 보장으로 표현하지 않는다. |
| 읽기 제외 경로 | 사용자가 지정한 파일과 디렉터리 | 모델 문맥에 넣지 않는다. 실행된 명령이 직접 읽는 것은 §9의 격리 수준에 따른다. |

- [설계] 첫 버전의 보호 범위는 사용자가 명시적으로 등록한 문자열 값과 텍스트 형식 자료다. 숫자, 표, 구조가 있는 문서 형식의 치환은 첫 버전이 약속하는 범위가 아니며 §10의 형식별 지원 구분을 따른다.
- [설계] 다음은 보장하지 않으며 문서와 제품 설명에 그렇게 적는다.
  - 임의로 인코딩·분할·변환된 비밀의 완전 탐지.
  - 프롬프트 주입의 완전 방어.
  - 등록되지 않았고 패턴에도 맞지 않는 민감정보의 탐지.
- [설계] 치환 계층이 오류나 시간 초과를 내면 전송하지 않는다. 가림 없이 보내는 대체 경로는 두지 않는다.

## 2. 용어

| 용어 | 뜻 |
| --- | --- |
| 원본 스냅샷 | 읽은 시점의 원문 바이트와 그 해시. 로컬에만 있다. |
| 가림 문맥 | 원본에서 비밀을 토큰으로 바꾼 사본. 모델이 보는 유일한 형태다. |
| 구간 대응 | 가림 문맥의 각 토큰 위치와 원본 스냅샷의 바이트 구간을 잇는 표. |
| 토큰 | 비밀을 대신하는 자리표시자. 값에서 유도하지 않고 무작위로 발급한다. |
| 금고 | 토큰과 원문의 대응표를 보관하는 로컬 암호화 저장소. |

## 3. 치환

- [설계] 모델에 전달되는 모든 텍스트는 하나의 치환 계층을 통과한다. 사용자 입력, 파일 내용, 파일 경로, 도구 출력, 오류 메시지가 모두 해당한다.
- [설계] 같은 범위 안에서 같은 원문은 같은 토큰을 받는다. 범위가 세션인지 프로젝트인지는 [미정]이다.
- [설계] 토큰은 값의 해시로 만들지 않는다. 해시 기반 토큰은 짧은 값의 추측과 세션 간 연결을 허용한다.
- [설계] 첫 버전의 토큰은 문자열 값을 대신하는 한 가지 형태만 둔다. 숫자 자리처럼 자료형이나 문법을 보존해야 하는 치환은 첫 버전에서 지원하지 않으며, 지원 형식은 §10에서 구분한다.
- [설계] 등록한 비밀은 원문 외에 정해진 변형도 일치 대상으로 삼는다. 초기 목록 후보는 Base64, URL 인코딩, JSON 이스케이프, 16진 표기다. 목록 밖의 변형은 탐지를 보장하지 않는다.
- [설계] 오탐을 줄이기 위해 잠금 파일의 무결성 해시처럼 공개된 고엔트로피 값은 제외 규칙으로 관리한다. 명시 등록한 비밀은 이 제외 규칙보다 우선하며, 같은 값이 공개 해시와 겹쳐도 치환한다.

## 4. 변경 적용과 코드 구간 대응

AGENTS.md는 전체 문자열의 무조건적인 원문 복원을 금지한다. 변경 적용은 다음 순서로 설계한다.

1. 모델은 가림 문맥을 기준으로 변경을 제안한다.
2. 엔진은 변경을 가림 문맥에서 대조한다. 대상 파일의 현재 해시가 원본 스냅샷과 다르면 적용하지 않고 다시 읽는다.
3. 변경이 건드리지 않은 비밀 구간은 문자열을 다시 치환하지 않고 구간 대응으로 원본 바이트를 그대로 유지한다.
4. 변경이 토큰을 새 위치나 다른 파일에 넣으면 §5의 권한이 없는 한 변경 전체를 거부한다. 같은 파일 안이라는 이유로 복원하지 않는다.
5. 쓰기는 파일 단위로 원자적으로 수행한다. 일부만 쓰인 상태를 남기지 않는다.

미등록·변형 토큰은 다음과 같이 처리한다. [설계]

| 상황 | 처리 |
| --- | --- |
| 금고에 없는 토큰 형태의 문자열 | 변경 전체를 거부하고 모델에 사유를 가림 상태로 알린다. |
| 토큰의 일부만 남거나 대소문자·길이가 바뀜 | 복원을 추측하지 않고 변경 전체를 거부한다. |
| 다른 범위에서 발급된 토큰 | 복원하지 않는다. |
| 모델이 토큰을 새 위치나 다른 파일에 복사함 | §5의 목적·필드·범위 권한이 없으면 변경 전체를 거부한다. |
| 응답 스트림에서 토큰이 조각으로 나뉘어 도착함 | 토큰이 완성될 때까지 버퍼에 두고 판정한다. |

모델이 비밀의 길이나 형식을 추론해야 하는 작업은 가림 상태에서 정확도가 떨어질 수 있다. 이 한계는 숨기지 않고 사용자에게 표시한다.

## 5. 목적지별 복원 제한

[설계] 복원 여부는 엔진 정책이 목적지 종류로 결정한다. 모델 출력, 프로젝트 문서, 확장은 복원 범위를 넓힐 수 없다.

로컬 파일이라는 이유만으로 복원하지 않는다. 첫 버전이 허용하는 것은 기존 보호 구간을 원래 위치에 유지하는 것뿐이다.

| 목적지 | 기본 정책 |
| --- | --- |
| 기존 보호 구간의 원위치 유지 | 허용. §4의 구간 대응으로 원본 바이트를 유지한다. 새로 복원하는 동작이 아니다. |
| 작업공간 안의 새 위치나 다른 파일 | 거부. 비밀, 목적, 대상 필드, 범위를 명시한 별도 권한이 있을 때만 허용한다. 권한의 형식과 부여 절차는 [미정]이다. |
| 로컬 화면 표시 | 허용. 화면 기록이나 공유로 나가는 경우는 [미정]이다. |
| 명령 인자와 환경변수 | 비밀과 명령의 쌍 단위로 사용자 승인. 기본은 거부다. |
| 작업공간 밖 파일 | 기본 거부. |
| 네트워크 요청, MCP 인자, Git 원격, 커밋 메시지 | 기본 거부. |
| 로그, 실행 기록, 오류 보고 | 복원하지 않는다. |

권한이 있는 복원은 다음 순서로 수행한다.

1. 도구 호출의 구조, 목적지, 정책을 확인한다. 구조를 해석할 수 없는 호출은 복원하지 않는다.
2. 권한이 허용한 필드의 토큰만 원문으로 바꾼다. 실행에 실제 값이 필요한 다른 필드에 미해결 토큰이 남으면 호출을 거부한다. 가림본의 기록과 표시는 실행과 구분한다.
3. 복원한 최종 인자를 다시 검사한다. 목적지와 범위가 권한과 일치하는지, 허용되지 않은 필드에 원문이 들어가지 않았는지 확인한다.
4. 검사를 통과한 호출만 실행한다.

새 위치 복원을 악용하는 사례는 [테스트 전략](testing.md) §6에서 검사한다.

## 6. API 인증키

- [요구] 첫 제공자는 Anthropic이다. [설계] 로컬 환경 변수 `ANTHROPIC_API_KEY`를 사용한다.
- [설계] 인증키는 전송 계층만 보유한다. 요청 헤더에만 넣고 모델 문맥, 도구 환경, 세션 기록, 로그에 넣지 않는다.
- [설계] 인증키는 등록한 비밀로 자동 등록한다. 파일이나 명령 출력에 같은 값이 나오면 치환된다.
- [설계] 실행하는 명령의 환경변수에서 인증키를 제거한다.
- [설계] 전송 계층의 오류 메시지와 디버그 출력에서 헤더 값을 지운다.

## 7. 로그, 세션, 금고

- [설계] 도구 출력은 치환한 뒤에만 실행 기록과 로그에 쓰고 모델에 전송한다. 치환 전 출력을 먼저 기록하는 순서는 허용하지 않는다.
- [설계] 디스크에 남는 실행 기록, 로그, 진단 자료는 가림본만 담는다.
- [설계] 원문 문자열과 가림 문자열을 타입으로 구분해, 기록 계층이 원문을 받을 수 없게 한다.
- [설계] 되돌리기용 원본 스냅샷은 원문을 담으므로 일반 로그나 실행 기록과 분리한 저장소에 둔다. 접근은 변경 적용과 되돌리기 경로로 제한하고 Git 추적에서 제외한다.
- [미정] 원본 스냅샷의 보관 위치, 암호화 여부, 접근 통제 방법, 수명과 삭제 시점.
- [설계] 금고는 실행 기록과 분리해 저장한다. 금고와 실행 기록은 Git 추적 대상에서 제외한다.
- [미정] 영구 금고의 구현 시점. 첫 버전이 실행 중에만 유지되는 대응표로 시작할지, OS의 자격증명 보호 기능으로 암호화한 영구 금고를 처음부터 둘지 정하지 않았다.
- [설계] 금고나 대응표가 삭제되거나 실행 종료로 사라지면 그 범위의 토큰은 원문으로 복구할 수 없다. 남은 기록과 가림 상태의 산출물에서도 마찬가지다. 이 점을 사용자에게 명시한다.
- [미정] 금고의 보존 기간과 삭제 절차, 범위가 다른 실행 기록을 합칠 때의 토큰 충돌 처리.

## 8. 치환이 적용되어야 하는 경로

[설계] 외부로 나가는 경로는 모두 같은 치환 계층을 지난다. 경로마다 따로 구현하지 않는다.

| 경로 | 요구되는 처리 |
| --- | --- |
| 도구 출력과 오류 | 치환한 뒤에만 기록하고 모델에 돌려준다(§7). 명령이 비밀을 변환해 출력하면 놓칠 수 있다(§1). |
| MCP | 송신 인자와 수신 결과에 모두 적용한다. 원격 MCP 서버는 외부 전송 목적지이며, 수신 결과는 신뢰하지 않는 입력으로 다룬다. |
| 임베딩 | 외부 임베딩 API도 외부 전송이다. 가림본만 보낸다. 로컬 색인에 원문을 둘지는 [미정]이다. |
| 이미지와 스크린샷 | 텍스트 치환이 적용되지 않는다. 별도의 로컬 가림 처리(영역 가림, 문자 인식 기반 탐지 등)를 거친 것만 전송한다. 그 처리기가 준비되기 전에는 기본값을 전송 차단으로 둔다. 문자 인식 기반 탐지는 최선 노력이다. |
| 재시도 | 처음 보낸 가림 요청을 그대로 다시 보낸다. 재시도 때 원문에서 다시 조립하지 않는다. |
| 문맥 요약과 하위 작업 | 초기 범위에 없는 기능이다. 추가할 때 가림 문맥만 입력으로 쓰고 토큰 범위를 유지한다. |
| 사용량·오류 보고 | 외부로 보내는 기능을 둔다면 가림본만 사용한다. 둘지는 [미정]이다. |

## 9. 실행 격리

- [설계] Git worktree는 파일 변경을 분리하는 수단이다. 파일 접근이나 네트워크를 막는 보안 경계가 아니다.
- [설계] 치환 계층은 LLM으로 가는 경로만 통제한다. 에이전트가 실행한 명령은 디스크의 원문을 읽고 네트워크로 보낼 수 있다. 이 경로는 치환으로 막을 수 없다.
- [설계] 초기 CLI는 다음을 적용한다.
  - 명령 실행 전 사용자 승인 또는 허용 목록 판정.
  - 자식 프로세스 환경변수에서 등록한 비밀 제거.
  - 작업 디렉터리 고정.
- [설계] 위 조치는 OS 수준 강제가 아니다. 자식 프로세스의 파일·네트워크 접근을 강제로 제한하려면 OS별 격리 실행기가 필요하다. 그것이 없는 동안 "네트워크 차단"이나 "파일 접근 차단"을 제품 기능으로 표현하지 않는다.
- [설계] 승인 없이 연속 실행하는 방식과 자기 개발 후보의 실행은 격리 수준이 정해진 뒤에 범위를 넓힌다.
- [설계] 셸, 확장, MCP의 실행 권한은 모델 출력이나 프로젝트 문서가 확대할 수 없다(AGENTS.md).
- [미정] OS별 격리 실행기의 도입 시점과 1차 대상 OS.

## 10. 범용 작업 산출물

[요구] Codaryn은 코딩 외에 문서 작성, 자료 분석, 파일 정리도 수행한다. [설계] 이 산출물에도 같은 정책을 적용한다.

정책은 같지만 형식마다 지원 수준이 다르다. 지원하지 않는 형식을 지원하는 것처럼 표현하지 않는다.

| 형식 | 첫 버전 처리 |
| --- | --- |
| 텍스트 파일(소스 코드, Markdown, 일반 텍스트)과 파일 경로 | 지원 대상. 등록한 문자열 값을 치환하고 §4의 구간 대응을 적용한다. |
| 텍스트 기반 표와 데이터(CSV, JSON 등) | 텍스트로 다룬다. 등록한 문자열 값만 치환한다. 숫자 값의 치환, 자료형과 집계 결과의 보존은 지원하지 않는다. |
| 구조가 있는 문서 형식(워드프로세서, 스프레드시트, PDF 등) | 미지원. 구간 대응이 설계되지 않았다. 기본은 모델 전송과 가림 상태의 수정을 하지 않는 것이다. |
| 이미지와 스크린샷 | §8을 따른다. |

- 미지원 형식의 자료는 조용히 건너뛰지 않고, 처리하지 않았다는 사실과 사유를 사용자에게 알린다.
- 문서 형식의 속성 정보(작성자, 수정 이력, 숨은 시트나 주석)는 본문과 별도로 다루어야 한다. 형식 지원을 추가할 때 함께 설계한다.
- 산출물 파일에 쓰는 것은 §5를 따른다. 외부 발송은 네트워크 목적지로 판정한다.
- [미정] 숫자와 표의 자료형·의미를 보존하는 치환, 구조가 있는 문서 형식의 지원 순서와 시점.

## 11. 미정 항목 요약

- 토큰 범위(세션 또는 프로젝트), 영구 금고의 구현 시점과 수명.
- 원본 스냅샷의 보관 위치·보호 방법·수명, 새 위치 복원 권한의 형식과 부여 절차.
- 최선 노력 탐지의 대상 범위(개인정보, 사내 식별자 포함 여부).
- 이미지 로컬 가림 처리기와 OS별 격리 실행기의 방식, 도입 시점, 대상 OS.
- 로컬 모델 사용 시 치환 적용 여부.
- 숫자·표의 보존 치환과 구조가 있는 문서 형식의 지원 순서.
