## 2. 복원과 옮긴 토큰 (`exp/gateway.mjs`)

- **`resolveToolArgs`**: 영폭 공백으로 끊긴 값이 든 경로는 원래 바이트 그대로 복원된다.
- **경로로 옮긴 토큰**: 토큰을 다른 경로(`copy-<토큰>.txt`)로 옮기면 구분 문자도 따라간다. 토큰이 가리키는 범위가 구분 문자를 포함하기 때문이다. 쓰기 경로로 복원했을 때 작업 공간의 판정:

  | 끊은 문자 | 판정 |
  |---|---|
  | 줄바꿈 | `invalid_path`(거부) |
  | 영폭 공백, soft hyphen | 받아들인다 |

  받아들인 경우 파일 이름에 값과 보이지 않는 문자가 든다. 경로 복원은 원래 허용된 동작이다(`restoreFields: ["path"]`). 끊기지 않은 값의 토큰을 경로에 쓰는 것과 노출 정도가 같아 새 문제로 보지 않는다.
- **명령 인자**: 복원 대상이 아니다(`run_command`는 `cwd`만). 토큰을 넣으면 `unresolved_token`이다. 그래서 구분 문자를 명령 인자로 들여보낼 길이 없다.
- **`rebuildDocument`**

  | 모델의 수정 | 결과 |
  |---|---|
  | 보호되지 않은 줄 고침 | 원본 바이트에 그 고침만 더해 다시 쓴다 |
  | 보호 줄 순서 바꿈 | `protected_span_violation` |
  | 토큰을 새 줄에 복사 | `protected_span_violation` |
  | 토큰을 같은 줄 안에서 옮김 | `protected_span_violation` |

  그래서 문서 안에서는 토큰과 함께 구분 문자가 다른 자리로 갈 수 없다.

## 3. 겹침, 이웃, 보호 줄, 재가림

- **겹침**: 두 등록 값이 겹치게 끊겨 있으면 한 토큰으로 합쳐지고, 원래 바이트로 다시 쓰인다.
- **이웃**
  - 이웃한 두 줄의 두 값은 두 토큰이 되고, 줄바꿈은 토큰 밖에 남는다.
  - 끊긴 값과 정확한 값이 바로 붙어 있으면 한 토큰이다(겹치거나 맞닿으면 합친다는 기존 규칙).
- **퍼징**: 무작위 글 4,000개로 확인했다. 조건은 두 값, 값마다 구분 문자 0~3개(11종, BMP 밖 포함), 이모지·é·단어를 둘레에 둔 것이다.
  - 입력 자체가 잘 짜인 3,984개: 두 번 가려도 같음, 가린 글을 다시 가려도 같음, 다시 쓰기 정확, 남은 글자 0, 결과에 짝 없는 대리 문자 0
  - 나머지 16개: 생성기가 앞서 넣은 BMP 밖 구분 문자의 두 반쪽 사이에 다른 문자를 넣어, 입력에 짝 없는 대리 문자가 생긴 경우다. 이때는 값이 가려지지 않는다. I-3과 같은 부류다(짝 없는 대리 문자는 구분 문자가 아니다).

## 4. 오탐과 시간 (`exp/perf-fp.mjs`)

**시간.** main / security-core 순서다(ms).

| 글 | 256 KiB | 1 MiB |
|---|---|---|
| 평문, 등록 값 2개 | 0 / 16 | 1 / 42 |
| 평문, 등록 값 32개(변수 파일 같은 값 30개) | 2 / 15 | 9 / 59 |

| 영폭 공백만 | 0 / 10 | 1 / 28 |
| 줄마다 끊긴 키 | 0 / 16 (토큰 2,405) | 2 / 67 (토큰 9,620) |

- 크기에 비례해 늘고 제곱으로 늘지 않는다.
- 구간마다 구분 문자를 뺀 글을 한 번 만들고, 그 구간 밖은 보지 않는다.
- 하한은 코드 포인트로 센다: 15 코드 포인트(23 UTF-16 단위) 값은 끊겨도 가리지 않고, 16 코드 포인트는 가린다. 커밋의 결정과 같다.

### I-1 (정보) 단어로 된 16 코드 포인트 이상의 등록 값은 평범한 글에서 공백을 건너 이어 붙어 가려진다

| 등록 값 | 글 | security-core | main |
|---|---|---|---|
| `summer2026winter` | `the summer 2026 winter schedule` | 가림 | 그대로 |
| `releasenotes2026` | `see the release` / `notes 2026 draft`(두 줄) | 가림 | 그대로 |
| `My Awesome Application` | `My  Awesome` / `Application is the title` | 가림 | 그대로 |
| `notapassword1234` | `this is not a password 1234 times` | 가림 | 그대로 |
| `1234 5678 9012 3456` | 카드 번호처럼 줄을 나눠 쓴 글 | 가림 | 그대로 |
| 12 코드 포인트 값 | (하한 아래) | 그대로 | 그대로 |

- 변수 파일의 값은 8자 이상이면 모두 등록된다. 그래서 사람이 쓴 문구 같은 값이 등록될 수 있다.
- 가려진 줄은 보호 줄이 되어 모델이 고칠 수 없다.
- 기밀성 쪽으로는 안전한 방향이다. 등록 값의 글자가 같은 순서로 공백만 사이에 두고 나타난 것이라 실제로 끊긴 값일 수도 있다. 정확한 문구는 main도 가렸다.
- 그래서 정보로 둔다. 사용 문서에 "변수 파일 값은 공백을 무시하고도 찾는다"는 한 줄을 권한다.

### I-4 (정보, 기존 동작) 이미 발급된 토큰이 많은 글을 다시 가리면 토큰 수에 비례해 느려진다

- 1 MiB 글에 토큰 7,490개를 담아 다시 가리면 main 1,999 ms, security-core 1,947 ms다.
- 원인은 토큰마다 구간을 나누고, 정확한 일치 검색이 구간 끝을 넘어 글 끝까지 찾는 기존 코드다.
- 이번 변경이 더한 비용은 없다. 구분 문자를 뺀 글은 구간 안에서만 만든다.
- 로컬 글에 발급된 토큰이 많이 들어갈 일은 드물어 정보로만 적는다.

## 5. BMP 밖 문자와 대리 문자 쌍

이모지 넷과 글자 16개로 된 값(20 코드 포인트)으로 확인했다. 각 경우 모두: 토큰 하나, 결과에 짝 없는 대리 문자 없음, 다시 쓰기 정확.

| 경우 | 결과 |
|---|---|
| U+E0041(BMP 밖 Cf)로 글자 사이를 끊음 | 위와 같음 |
| 이모지 바로 뒤 영폭 공백 | 위와 같음 |
| 이모지 사이 영폭 공백 | 위와 같음 |
| 앞뒤에 다른 이모지 | 이모지는 토큰 밖에 그대로 |

- `compactView`는 코드 포인트 단위로 걷는다. 범위 끝은 마지막 코드 포인트의 마지막 단위 다음이라, 쌍을 쪼개지 않는다.

### I-3 (정보) R-25b L-1의 문자는 가림에서도 빠진다

- 가림은 거부와 같은 문자 집합(`KEY_SEPARATOR_PATTERN_SOURCE`, 공백·Cc·Cf)을 쓴다.
- 그래서 다음 문자로 끊긴 등록 값은 가리지 않는다(security-core에서 확인): 이체 선택자 U+FE0F, 한글 채움 문자 U+3164, 점자 빈칸 U+2800, 짝 없는 대리 문자.
- R-25b L-1(거부 쪽)의 판단이 정해지면 가림도 같이 맞추기를 권한다. 집합을 넓히거나, 16 코드 포인트 이상 등록 값을 글자·숫자만 남긴 글에서도 찾는다.
  - 글자·숫자만 남기면 보이는 문장부호까지 범위에 들어간다. 그래서 I-1의 과한 가림이 늘어나는 것과 견줘 정해야 한다.

### I-2 (정보) 줄에 걸쳐 끊긴 값은 두 줄을 한 보호 줄로 만든다

- 예: `api_key = <앞>` 줄과 `<뒤>  # rotate` 줄이 가린 글에서 `api_key = <토큰>  # rotate` 한 줄이 된다.
- 그래서 둘째 줄의 주석을 고치면 `protected_span_violation`이다(재현함).
- 원래 바이트를 지키려는 설계의 결과다. 줄 수도 줄어든다(6줄 → 5줄).
- 모델이 그 줄을 고쳐야 하는 일은 드물어 정보로 둔다. 사용 문서나 거부 문구에서 알려 주면 충분하다.

## 6. 끊기지 않은 값의 기존 동작

- 무작위 글 3,000개로 비교했다. 글에는 정확한 값과 등록된 변형 형식(Base64, URL 인코딩, hex)이 섞였고, 둘레에 공백·줄바꿈·탭·이모지·é를 두었다.
- 고정 난수원으로 두 판을 비교한 결과, 가린 글이 3,000개 모두 같았다.
- 토큰 형식은 `[[CODARYN_SECRET:` + hex 16자 + `]]` 하나뿐이다.
- 시험
  - `tests/unit/privacy/split-secret.test.ts`와 `tests/unit/engine/dr40-split-secret.test.ts`: 26/26 통과
  - `tests/unit/privacy/` 전체: 53/53 통과
  - 엔진 시험의 변경은 todo 표시를 지운 것뿐이고, 단언(요청·journal·결과 0)은 그대로다.
