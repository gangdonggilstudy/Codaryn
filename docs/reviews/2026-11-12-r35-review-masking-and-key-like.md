### I-1 (정보) 키 같지 않은 등록 값이 드문 문자로 끊기면 거부·가림·출력 가림이 모두 빠진다

**재현**: 실제 CLI, Anthropic 실행. `OPENAI_API_KEY`에 값을 두고 goal에 넣었다. 칸은 요청에 간 값의 글자 수다.

| 등록 값 | 끊은 문자 | main | 고정 판 |
|---|---|---|---|
| `sk-`+`local-0123456789abcdef`(소문자·숫자 23자, 키 같지 않음) | U+FE0F, 가운뎃점, 한글 채움 문자 | 거부, 요청 0 | **실행, 23/23자가 요청에** |
| 같은 값 | 줄바꿈, 영폭 공백, 끊지 않음 | 거부 | 거부 |
| `ABCDEF0123456789WXYZ`(대문자·숫자 20자, 키 같지 않음) | U+FE0F, 가운뎃점, 한글 채움 문자 | 거부 | **실행, 20/20자** |
| 같은 값 | 줄바꿈, 영폭 공백, 끊지 않음 | 거부 | 거부 |
| 소문자 hex 40자(32자 이상이라 키 같음) | 위의 모든 경우 | 거부 | 거부 |

- 출력 가림(`hideKeys`)도 같다. U+FE0F로 끊긴 위 23자 값은 고정 판에서 그대로 나오고, main은 가렸다.

**원인**: DR-43 (c)가 의도한 대로다.
- 거부(`createKeyValueCheck`), 실행 안의 가림, 출력 가림 셋 모두 "키 같은 값"일 때만 글자·숫자 비교를 한다.
- 그래서 키 같지 않은 값은 정확한 비교와 구분 문자 비교만 받는다. 구분 문자는 공백·제어·서식 문자다.
- 이체 선택자·가운뎃점처럼 구분 문자가 아닌 문자로 끊기면 셋 다 놓친다. 값이 요청과 기록에 그대로 간다.

**정보로 두는 까닭**
- R-32 L-1의 오탐을 없애려고 고른 맞교환이다.
- 실제 형식 키에는 생기지 않는다(위의 키 70,000개).
- OpenAI 호환 제공자의 흔한 키 모양도 대부분 키 같은 값이다: 64자 hex, 32자 hex, 대소문자 섞인 긴 토큰.
- 키 같지 않으면서 20자 이상인 값을 키 변수에 두는 것은 주로 로컬 서버의 자리 채움 값이다.
- 드문 문자로 끊기는 일도 드물다.

**제안**: 사용 문서에 한 줄을 둔다. "키 변수에 둔 짧거나 한 가지 대소문자만 쓴 값은, 보이지 않는 문자로 끊기면 거부도 가림도 되지 않는다."
