## U-44 — 판단: 병합해도 된다

- **바뀐 것:** `plan.formUnknown` 두 언어에 한 문장이 더해졌다. "실행을 시작할 때 `--config`나 `--vars-file`을 썼으면 같은 파일로 그것도 더하세요. 그 실행의 설정 파일이 없으면 적용이 그 실행의 설정을 읽지 못합니다."
- **유닛 시험(`u44-form-unknown.test.ts`):**
  - 화면 명령이 빼먹는 작업 지정 옵션(`--profile`, `--config`, `--vars-file`)을 문구가 모두 말하는지 CLI의 `TASK_FORM_USAGE`와 대조한다.
  - 채운 명령을 `parseApplyArgs`로 읽는다.
- **실험 B(`r63-apply.test.mjs`): 안내대로 채운 명령을 그 판의 실제 CLI로 돌렸다.**
  - 계획은 `run --task <파일> --vars-file <파일>`로 만들었다. task의 `secretEnv` 값은 변수 파일에만 있다.
  - 꼴 2에 쓴 설정 파일에는 `secretEnv`와 한도가 있다.
  - 경우마다 새 계획을 만들었다.

  | 명령 | 결과 |
  | --- | --- |
  | 꼴 1 그대로(`--vars-file` 없음) | `secret_env_missing`(종료 2), 옮긴 것 없음. 문구가 더하라고 한 것을 빼면 이렇다 |
  | 꼴 1 + `--vars-file`(실행을 시작한 대로) | 종료 0, `apply` `done`, 옮겨짐 |
  | 꼴 2 그대로 | `invalid_config`(한도 없음), 옮긴 것 없음 |
  | 꼴 2 + `--config`만 | `secret_env_missing`, 옮긴 것 없음 |
  | 꼴 2 + `--config` + `--vars-file` | 종료 0, `done`, 옮겨짐 |
  | 꼴 1 + 실행이 쓰지 않은 `--config`까지 | `invalid_task`(task 한도가 설정 파일 한도를 넘음), 옮긴 것 없음. 문구의 "썼으면"이 맞다는 확인이다 |

- **판단:** 안내대로 채운 명령은 실제 CLI로 돈다. 빼먹거나 더 넣으면 어느 경우도 옮기지 않고, 오류가 무엇이 빠졌는지 말한다.

## 정보 (건수에 넣지 않음)

- **I-1 (U-40) 두 문구의 표류:** GUI 문구 `run.masking`은 공용 카탈로그의 `summary.masking`을 쓰지 않고 GUI 카탈로그에 따로 있다. 지금은 같고 유닛 시험이 대조하므로, CLI 문구가 바뀌면 시험이 잡는다.
- **I-2 (U-40) `registeredValues` 0:** GUI는 `{0,0}`을 줄로 보인다. 엔진은 등록 값이 0이면 필드를 내지 않고, CLI report는 1보다 작은 `registeredValues`를 거부한다. 그래서 실제로 이 줄이 뜨는 길은 없다. CLI 끝 요약의 `isCount`도 0을 받으므로 둘이 맞다.
- **I-3 (U-44):** 안내는 "썼으면 더하세요"이다. 실험처럼 실행이 쓰지 않은 `--config`를 더하면 `invalid_task`가 된다(옮긴 것 없음). 문구가 맞고 바꿀 것이 없다.
