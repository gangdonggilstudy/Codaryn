## 2. 낮음

### R64-L1 `plan`·`apply`·`review`의 도움말 목록에 `--workflow`가 없다

- 위치: `src/cli/help.ts:86-88`의 `COMMAND_OPTIONS`. 세 명령의 해석기는 `TASK_FORM_OPTIONS`(`src/cli/args.ts:396`)로 `--workflow`를 받는다. 사용법 줄에도 `[--workflow <id>]`가 있다. 그러나 옵션 목록에는 없고, 그 글(`help.option.workflow`)도 없다.
- 재현(P, `P.log`)
  1. 세 명령의 기본 인자에 `--workflow organize`를 더하면 `unknown or repeated option`이 아니다.
  2. `plan --run <id> --workspace <ws> --workflow no-such-workflow`와 `review …`는 `invalid_config`(종료 2), `workflowRef names no built-in workflow …`다. 값을 실제로 쓴다.
  3. `apply --workspace … --workflow organize`는 R-61에서 쓴 간편 형식이다.
- 영향: 간편 형식으로 계획을 보거나 적용·확인하는 사람은 작업 종류를 줄 방법을 도움말에서 찾지 못한다. `run`에서 같은 빈 곳(UXM-20, 사용 안내 16절)이 이미 알려져 있고, 이 단위가 그것을 세 명령에 옮겨 놓았다.
- 고칠 방향(제안): `HELP_OPTIONS`에 `workflow`를 더하고 두 언어 글을 만든다. `run`, `plan`, `apply`, `review`의 목록에 사용법 줄 순서대로 넣는다. `changes`는 받지 않으므로 넣지 않는다.

### R64-L2 `apply` 설명의 터미널 조건이 main보다 거칠어졌다

- 위치: `src/i18n/en.ts:203`(`help.command.apply`)과 `ko.ts`의 같은 줄. 새 글은 "At a terminal the result's JSON line is printed only with --json or --quiet"(한국어 "터미널에서는 --json 또는 --quiet 옵션을 줄 때만 결과의 JSON 한 줄을 냅니다")다.
  - main `9934a9a`의 글은 `src/cli/help.ts:27-28`에서 "At a terminal (stdout and stderr both) …"였다. U-45(R-58 R58-L1·L2)가 고친 문장이다.
- 재현(D, `D.log`): 같은 계획을 `apply --digest`로 적용한다(`--json`, `--quiet` 없음).
  - stdout과 stderr를 모두 터미널로 표시: 종료 0, stdout 비어 있음
  - stdout만 터미널로 표시(stderr는 파일): 종료 0, stdout에 `kind:"apply"`, `done`/`verified` JSON 한 줄. 도움말과 다르다.
- 영향: stderr를 파일로 모으는 사람이 화면에 JSON이 나오는 것을 도움말로 설명할 수 없다. R-58의 고침 하나가 글에서 되돌려졌다. 동작은 맞고 글만 틀렸다.
- 고칠 방향(제안): 두 언어 모두 "터미널(stdout과 stderr 모두)"을 되살린다. 계약 문서(`docs/cli-contract.md` 630행 근처, U-45의 규칙)와 맞춘다.

### R64-L3 `changes` 설명이 글이 보이는 조건을 다 말하지 않는다

- 위치: `src/i18n/en.ts:205`(`help.command.changes`)와 `ko.ts`의 같은 줄. "a file's changed lines only when the current secrets mask it as the run did"다.
- 재현(D, `D.log`): 같은 task로 실행 하나를 만든다.
  - 표시 없음: 파일의 글이 보인다(`after` 있음).
  - 그 실행 폴더에 `records-changed.json`을 두면: `--json`의 `recordsChanged: true`, 파일은 `after: null`, `unavailable: "masking_unverified"`. 가릴 값은 그대로인데도 글이 없다.
  - 사람용 출력은 스스로 두 조건을 말한다: `a file's text is shown only when the secrets registered now mask it as the run did and the file is as the run left it`.
- 영향: 도움말만 읽은 사람은 가릴 값이 같으면 글이 보인다고 생각한다. 실제 조건은 셋이다: 표시가 없음, 파일이 실행이 남긴 그대로임, 가릴 값이 같음. 지시가 말한 "낡은 사실"이 반쯤 남았다.
- 고칠 방향(제안): 두 언어 글에 "파일이 실행이 남긴 그대로이고, 실행에 기록 변경 표시가 없을 때"를 더한다. 사람용 출력의 문장과 같게 하면 된다.

## 3. 정보

- **R64-I1 `--task`의 옵션 글이 "실행할 task 파일"이다.** `help.option.task`(`en.ts:207`)를 다섯 명령이 그대로 쓴다. `plan`·`review`·`changes`·`apply`는 task를 실행하지 않는다. 설정·검증기·가릴 값을 읽는 데 쓴다. "계획 실행에 쓴 task 파일" 같은 글이 더 맞다.
- **R64-I2 `--workspace`의 글이 생략 규칙을 말하지 않는다.** 둘 다 없으면 `plan`·`changes`는 현재 폴더를 쓴다. `apply`·`review`·`cleanup`은 꼭 줘야 한다(U-17, R-61). 지금 글은 "작업 공간 폴더"뿐이다.
- **R64-I3 `apply`의 `--json` 줄은 `report`의 글("결과를 JSON 한 줄로 냅니다")을 그대로 쓴다.** `apply`는 터미널이 아니면 `--json` 없이도 JSON을 낸다. R-58의 R58-L2 가운데 `run`·`revert`에 남은 것과 같다.
- **R64-I4 새 옵션 글의 사실도 맞다.**
  - `--run <run id>`(`apply`): `latest`를 받지 않는다(R-60).
  - `--digest`: 앞 12자 이상. 없으면 터미널에서 묻는다(R-52b).
  - `--confirm`: 미리보기 뒤 상태가 바뀌면 `cleanup_plan_changed`(E)다.
  - `--older-than`, `--run <id>[,<id>...]`, `--discarded-run`, `--include-not-reverted`, `--delete-discarded`: D에서 봤다.
  - `--note`의 500자와 키 값 거부는 돌려 보지 않았다.
