## 중점별 결론

### 계획 화면에 가는 줄이 U-32 때와 같은가

**같다.**

실험 A의 방식: 각 판의 `main.ts`가 짜는 그대로 `modelText`를 만들어 같은 글을 넣었다.
- 옛 방식: main의 GUI 빌드 `modelTextOf(quoteModelText, MODEL_TEXT_PREFIX, …)`
- 새 방식: 2337e69의 GUI 빌드 `modelTextOf(app.modelTextRows, …)`

| 비교 | 넣은 것 | 결과 |
| --- | --- | --- |
| 줄 | 고정 글 16개 + 무작위 글 2000개, 키 값 없이 한 번·설정된 키 값 하나로 한 번 | 4032건 모두 같다 |
| 창이 받는 보기(`planValue` → `toPlanView`) | 위 글 2016개 | 2016건 모두 같다 |
| 최대 줄 수 | — | 둘 다 20(+`… (+N)` 한 줄) |

- 고정 글은 R-59의 글들이다: HTML, 양방향 문자, zero-width, ANSI, NEL·U+2028, TAB·CRLF, 긴 낱말, 줄바꿈 240개, 키 모양, 설정된 키 값, 토큰 모양, 넓은 글자·이모지, 600낱말, 빈 글.
- 무작위 글은 글자·공백·제어·보이지 않는 글자·양방향 문자·키 조각·토큰 조각을 섞었다.
- 새 방식은 엔진 호스트 자신의 `hideAllKeys`를 먼저 거치고, 앱 계층의 `keys` 선택은 쓰지 않는다(`model-text.ts` 머리말). 그래서 가림도 전과 같다.
- 유닛 시험 `u32-plan-view.test.ts`의 바뀐 곳은 그리는 함수를 `app.modelTextRows`로 바꾼 것뿐이다. 검사는 그대로이고 약해지지 않았다.

### modelTextRows가 없거나 다른 꼴일 때 닫힌 쪽으로 가는가

**간다.**

- `main.ts`는 `typeof appModule.modelTextRows === "function"`일 때만 `modelText`를 만든다. 아니면 요약을 보이지 않는다.
- `MODEL_TEXT_MAX_ROWS`가 개수가 아니면 20을 쓴다.
- 실험 B(`planValue` → `toPlanView`):

  | 경우 | 결과 |
  | --- | --- |
  | 없음 | 요약 없음, 계획 보기는 열림 |
  | 문자열을 돌려줌 | 요약 없음 |
  | 숫자 배열을 돌려줌 | 요약 없음 |
  | null을 돌려줌 | 요약 없음 |
  | 던짐 | 요약 없음 |
  | 100줄 | 21줄로 잘림 |
  | RLO·LF가 든 줄 | `shown`이 `?`로 바꿈 |
  | 5000자 한 줄 | 주 프로세스가 보기 전체를 `host_error`로 거부(정보 I-1) |

### 주 프로세스가 recordsChanged를 다시 검사하는가

**한다.**

- `toChangesReply`는 `value.recordsChanged ?? false`가 불리언이 아니면 보기 전체를 `host_error`로 거부한다.
- 실험 C:

  | recordsChanged | 주 프로세스 |
  | --- | --- |
  | `true` | 받음 |
  | `false`, 없음, `null` | `false` |
  | `"true"`, `1`, `0`, `{}`, `[]` | `host_error` |

- 엔진 호스트 `changesValue`는 `=== true`일 때만 `recordsChanged: true`를 넘긴다. `"true"`·`1`은 넘기지 않는다.
- 렌더러 `asChanges`도 `=== true`만 본다.

### 표시가 있는 실행에서 파일 글이 화면에 가지 않는가

**가지 않는다.**

- 실험 D의 방식: 앱 계층으로 실제 실행을 하나 돌렸다(NOTES.md 만듦). 그 뒤 records-changed 표시를 쓰고, `app.changes` → `changesValue` → `toChangesReply`로 받았다.

  | 실행 | recordsChanged | NOTES.md의 `after` | unavailable | 화면에 가는 글 |
  | --- | --- | --- | --- | --- |
  | 표시 전 | false | `# Notes\n` | null | 있음 |
  | 표시 뒤 | true | null | `masking_unverified` | 0개 |

- 글이 빠지는 것은 앱 계층이 정한다. store가 표시된 실행에 `shown` 기록을 주지 않기 때문이다(U-43, contracts/state.ts). GUI는 그것을 그대로 옮긴다(정보 I-3).
- 연기 시험 `changesRecordsChanged`: 경고가 첫 요소(`changes-records-changed`), 파일 2개 모두 글 숨김, 비교 0.
- 파일마다 `changes.unverifiedMarked`("이 실행의 기록이 실행 밖에서 바뀌었습니다")를 쓴다.

## 정보 (건수에 넣지 않음)

- **I-1 (기존, U-32부터):** 요약 줄 하나가 주 프로세스의 짧은 글 한도를 넘으면 요약만이 아니라 계획 보기 전체가 `host_error`다.
  - 실제 `modelTextRows`의 줄은 많아야 72열이라 생기지 않는다.
  - 엔진 호스트가 그런 줄을 버리고 요약만 빼면 더 부드럽다.

- **I-3:** 표시된 실행의 파일 글을 GUI가 따로 지우지는 않는다. 앱 계층의 판정(글 없음)에 기댄다. 지금은 그것으로 맞다. 앱 계층이 바뀌면 GUI에는 따로 막는 것이 없다.
