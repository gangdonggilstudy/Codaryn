## 2. 상한 근처 시간·메모리

각 측정은 **새 Node 프로세스**, 판별 3회, 기준/후보 순서를 번갈아 실행했다. 표 생성·모듈 로드·workspace 준비·사전 GC는 시간에서 제외하고, 실제 검증기 호출과 파일 읽기는 포함했다. 아래는 3회 중앙값. 메모리는 Node 런타임을 포함한 프로세스 최고 RSS의 근삿값이다(`resourceUsage().maxRSS`, 5 ms RSS 표본, 종료 시 RSS 중 최댓값). 시작 RSS는 약 64 MiB였다. OS 캐시를 비우지 않았으며 다른 사용자 프로세스의 부하는 통제하지 않았다.

42개 프로세스의 검증 결과는 모두 pass였고, 대응하는 두 판 결과 21쌍이 문자 단위로 같았다. 측정한 입력에서는 시간과 메모리가 모두 줄었다. 긴 칸 자체나 그룹 수에 따른 메모리 사용은 남으므로, 이 수치를 모든 입력의 고정 메모리 상한으로 해석하지 않는다.
