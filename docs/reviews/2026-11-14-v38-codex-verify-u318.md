## 변경 위치·다른 사유

- 후보 `gui/src/engine-host/history.ts:108`: `missing_record`이면 `shown()`에 원문을 넘기지 않고 null로 전송한다. 다른 사유는 기존 shown 처리를 유지한다.
- 후보 `gui/src/shared/ipc.ts:1687`, `:1730`: 보기의 경로가 nullable이 됐고, **옛 호스트처럼 원문 문자열이 들어와도** missing_record 경로를 버린다. null은 해당 사유에서만 받는다. undefined·숫자·객체·배열·boolean 경로는 계속 거부한다.
- 후보 `gui/src/main/ipc.ts:640`, `:660`, `:683`: preview·revert·consent 경로가 동일한 toRevertView를 거친다. 이번 동적 메인 핸들러 시험은 preview와 revert를 실행했다. consent 재시도 자체는 추가 실행하지 않았다.
- 후보 `gui/src/renderer/runs/runs-screen.ts:62`, `:64`: null 경로는 `?`, 해당 줄이 있으면 설명을 추가한다. 텍스트는 `gui/src/renderer/i18n/en.ts:444`, `ko.ts:446`이다.
- **변경 없는 사유:** changed_since_run, missing_snapshot, io_error, already_reverted, original_path_taken, unsafe_move. 각 사유를 호스트 변환·메인 검사·한/영 전체 화면의 preview/result에 넣었다. 경로와 줄 텍스트 24쌍이 같고, 숨김 설명이 새로 붙지 않았다. 실제 실행의 missing_snapshot 가림 경로도 유지됐다.
- CLI JSON과 앱 원래 응답의 원문 경로는 이 수정 범위 밖이며 그대로였다. 후보의 GUI 경계에서 그 값을 없애는지 판정했다.
