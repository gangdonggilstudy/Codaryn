## 3. 최종 가림 단계

구조화 report는 `src/app/app.ts:627`의 hideKeysInStrings→jsonLine, :632의 **전체 텍스트 hideKeys→jsonOutcome 재파싱**을 유지한다. Markdown은 :660의 기존 run/apply renderer 선택 뒤 :665에서 최종 hideKeys를 유지한다. formatter 실패의 invalid_run_record 문구와 최외곽 INTERNAL_ERROR도 보존됐다. 동작 비교와 원문 대조에서 마스킹 단계의 생략·재배열을 발견하지 못했다.

직렬화 경계의 internal_error는 이전부터 있던 기준 동작이다. 이를 고친 것으로 세지 않았고 이번 이행에서 임의로 바꾸지도 않았다. 과거 task의 secretEnv로 변조된 임의 기록을 모두 다시 가린다는 보장으로 해석하지 않는다.

선택한 U316 기존 시험은 추가로 ASCII JSON escape에서만 맞는 합성 현재 값, 여러 provider 변수, 제어 문자·한글·emoji·quote/slash와 Windows의 소문자 env 이름도 검사해 통과했다. 이 시험의 CLI 대조만으로 독립성을 주장하지 않고, 사전에 봉인한 공개 앱 결과를 주 근거로 삼았다.

- `src/app/app.ts:63` → `cli/report.js`: renderReport, renderApplyReport.
- `src/app/app.ts:64` → `cli/guard.js`: jsonLine.

- `cli/report.js` 모듈 자체도 cli/args.js, cli/guard.js, cli/human/index.js를 가져온다. 함수 호출을 없앴다고 이 모듈의 정적 의존성까지 없어진 것은 아니다.

다른 앱 기능을 위한 assemble/doctor/init/models/plan-commands/revert 등 CLI import도 그대로다. 빌드 JS의 정적 상대 import/export 경로를 조사한 `modules-v42.json`에서는 app/app.js의 직접 CLI 대상이 **base 8개 → head 9개**이고, 간접 전이로 닿는 CLI 모듈은 양쪽 **22개**다. 새 jsonLine 직접 import 때문에 직접 대상 하나가 늘었다. 앱 전체의 의존성이 0이라고 주장하지 않는다.

반면 readReport가 있는 app/report-read.js 자체의 전이 경로에는 CLI 모듈이 없었다. 이는 판독 규칙의 방향과 표시/직렬화의 공유 의존성을 구분한 결과다. 모듈 수는 정적 JS 상대 경로 기준이며 동적 기능 호출 횟수나 아키텍처 완료 판정이 아니다.
