## fs·oracle 실행 방식

실제 fs 관측은 exclusive 생성/충돌, CAS 일치·불일치·null, 누락 대상/부모, 최종 bytes/mode와 temp, rename EPERM/cleanup EBUSY를 포함한다. realpath→temp write(wx)→stat→chmod→read→expected→rename 순서가 그대로다. EPERM 후 rm EBUSY면 **EBUSY가 우선하고 temp가 남는** 기존 의미도 원래26 관측 및 새14시험에서 유지됐다. 추가 stat/chmod/read/temp 생성 오류와 getter 타이밍은 새 공개 시험이 확인했다. 문구의 정리나 race/security 정책 변경을 하지 않았다.

원본14개 파일과 seal.json/sha256을 oracle/에 exclusive 복사해 불변 보관했다. 원본 harness는 seal 검증 뒤 고정된 build/src/cli/models.js를 import하므로, **harness를 수정하지 않고** replay-head.mjs의 Node registerHooks가 그 정확한 URL 한 번만 head/dist/src/cli/models.js로 resolve한다. 나머지 import/입력/오류/경로 치환/JSON 출력은 원본 그대로다. replay-target.json이 유일한 요청/실제URL 및 legacy 함수가 후보 canonical 함수와 동일함을 기록한다. reference compiled 파일14seal을 head로 덮어 봉인을 우회하지 않았다. 코드가 OLD reference를 실행한 것도 아니다.

harness는 새 oracle/executions/head-001에만 썼고 원래 lexical/realpath 경계·링크 거부 및 rename 양쪽 guard를 유지했다. Windows 경로 JSON 문자열 일괄 치환/정규화 확대/capture/기대값 재생성/재봉인은 없다. harness의 d1a base 필드는 immutable corpus 출처이며 실제 실행 판은 setup.json/replay-target.json/final-verification.json에 구분했다.
