# 유닛 테스트 계획

담당 페르소나: 검증 엔지니어(주), 보안·개인정보 검토자(보조).

현재는 코드가 없는 설계 단계다. 아래 테스트는 작성되거나 실행된 적이 없다. 모듈 이름과 단계는 [아키텍처](architecture.md)와 [단계별 계획](roadmap.md)을, 검증 단계 구분은 [테스트 전략](testing.md)을, 치환과 복원 규칙은 [민감정보 처리](privacy.md)를 따른다.

표기: **[요구]** 사용자 확정 요구, **[설계]** Codex가 검토해 채택한 설계 선택, **[미정]** 결정하지 않은 항목.

## 1. 목적과 원칙

- [요구] 유닛 테스트도 구현 효율을 위해 설계해서 진행한다.
- [설계] 유닛 테스트는 해당 계약을 구현하기 전이나 구현과 같은 변경 단위에서 작성한다. 구현 뒤로 미루지 않는다.
- [설계] 대상은 위험 시나리오로 정한다. 커버리지 100%를 요구하지 않고, 수치를 채우려는 저위험 테스트를 만들지 않는다.
- [설계] 통과는 그 사례가 검사한 범위의 증거다. 보호된 검증기와 검증 보장 범위에 관한 규칙은 [테스트 전략](testing.md) §1, §4를 따른다.

## 2. 검증 층과 유닛 테스트의 한계

[설계] 다섯 층을 섞지 않는다. 이 문서는 첫 두 층만 다룬다.

| 층 | 실제로 쓰는 것 | 대신 넣는 것 | 키 |
| --- | --- | --- | --- |
| 순수 유닛 | 대상 함수와 메모리 안 자료 | 없음 또는 시계·난수 | 불필요 |
| 모의 adapter | 엔진과 모듈 연결 | 모델 응답, 명령 실행기, 시계 | 불필요 |
| 실제 프로세스 통합 | CLI 프로세스, 파일시스템, 자식 프로세스 | 모델 응답 | 불필요 |
| 실 API | Anthropic API | 없음 | 로컬 키와 명시 모델 |
| 외부 보호 검증 | 후보 밖의 고정 검증기 | 없음 | 불필요 |

유닛 테스트만으로는 다음을 입증하지 못하며 그렇게 보고하지 않는다.

- 실제 OS 격리와 네트워크 차단.
- 자식 프로세스의 실제 종료와 정리.
- 강제 종료나 전원 차단에서의 파일 원자성, 실제 심볼릭 링크 해석.
- 실제 모델의 응답 형태와 실제 API의 오류 동작.

이 항목들은 실제 프로세스 통합 또는 실 API 층에서 따로 검사한다.

## 3. 우선순위

| 등급 | 기준 | 규칙 |
| --- | --- | --- |
| P0 | 깨지면 비밀 유출, 사용자 자료 손실, 권한 이탈, 틀린 성공 보고로 이어지는 계약 | 해당 기능과 같은 변경에 포함한다. 없으면 그 기능을 완료로 보지 않는다. |
| P1 | 깨지면 잘못된 동작이지만 범위가 좁거나 다른 층에서 드러나는 계약 | 같은 단계 안에 추가한다. |

분기가 없는 전달 코드, 설정 상수, 자료형 정의는 유닛 테스트 대상에서 제외한다.

| PR-09 | P0·1 | 복원하면 실효 경로나 명령이 정책 밖이 되는 인자다 | 실효 인자를 재검사한다 | 거부하고 복원값을 버리며, 기록에는 가림 사유만 남는다 |
| PR-10 | P0·1 | 도구 결과에 등록한 비밀이 있다 | 결과를 처리한다 | 기록 계층과 모델 요청이 받은 값이 모두 가림본이다 |
| PR-11 | P0·1 | 치환기가 오류를 낸다 | 전송을 준비한다 | 모델 호출이 일어나지 않는다 |
| PR-12 | P1·1 | 등록한 비밀과 겹치지 않는 공개 해시가 제외 규칙에 해당한다 | 치환한다 | 토큰으로 바뀌지 않는다. 명시 등록한 비밀은 제외 규칙보다 우선한다 |

### 4.5 AnthropicAdapter

전송 경계만 대신 넣는다. 요청·응답 fixture는 공식 API 문서의 형식으로 만들며, 실제 API와의 일치는 실 API 층(1b)에서만 확인한다.

| ID | 등급·단계 | Given | When | Then |
| --- | --- | --- | --- | --- |
| AD-01 | P0·1 | 도구 정의와 도구 결과가 든 대화가 있다 | 요청으로 변환한다 | 도구 이름과 입력 스키마가 유지되고 각 결과가 해당 호출 식별자와 짝을 이룬다 |
| AD-02 | P0·1 | 도구 요청이 든 응답 fixture가 있다 | 제공자 중립 응답으로 변환한다 | 호출 이름, 인자, 식별자, 종료 사유가 맞다 |
| AD-03 | P0·1 | 등록되지 않은 도구, 스키마에 맞지 않는 인자, 길이 제한으로 잘린 응답이 있다 | 응답을 변환한다 | 형식 오류로 분류되고 도구가 실행되지 않는다 |
| AD-04 | P0·1 | 인증 실패, 한도 초과, 시간 초과가 주입된다 | 호출한다 | 종류별로 분류되고 재시도는 상한 안에서만 하며 재시도 본문이 처음과 같다 |
| AD-05 | P0·1 | 응답에 사용량이 있거나 없다 | 사용량을 집계한다 | 있으면 한도에 반영한다. 없으면 0으로 처리하지 않고 알 수 없음으로 표시하며, 토큰 한도를 확인할 수 없는 추가 호출은 중단한다 |
| AD-06 | P0·1 | 가짜 키가 설정되어 있다 | 요청을 만들고 오류를 일으킨다 | 키가 요청 본문, 오류 문구, 기록에 없다 |
| AD-07 | P0·1 | 키나 모델 설정이 없다 | 실제 호출 경로를 요청한다 | 전송 없이 거부한다 |

## 5. 대역과 결정성

- [설계] 대신 넣는 것은 외부 경계뿐이다: 모델, 시계, 난수, 명령 실행기, 전송 계층. 치환, 정책, 상태 기계 같은 내부 모듈은 실제 구현을 쓴다.
- [설계] 파일 동작은 가능하면 임시 디렉터리의 실제 파일로 검사한다. 오류 주입이 필요한 사례(WS-02)만 파일 계층을 대신 넣는다.
- [설계] 결정성은 고정 fixture, 가짜 비밀, 주입한 시계와 난수로 확보한다. 실제 비밀, 실제 시간, 네트워크에 의존하지 않는다.
- [설계] 가짜 비밀은 실제 키 형식과 구별되는 고정 값으로 두어 저장소 검사 도구가 실제 유출로 오인하지 않게 한다.

## 6. 피할 것

- 구현 내부 절차를 그대로 따라 쓰는 테스트. 관찰 가능한 결과(반환값, 파일 바이트, 상태, 기록 내용)로 판정한다.
- 호출 횟수만 확인하는 테스트. "호출이 없다"는 판정은 유출·재실행 방지 사례에만 쓴다.
- 대상 대부분을 대신 넣는 거대한 대역.
- 위험이 낮은 코드에 대한 형식적 테스트.

## 7. 실패와 회귀

- [설계] 새로 발견한 결함은 먼저 재현하는 회귀 사례로 추가한 뒤 고친다.
- [설계] 테스트를 삭제, 건너뛰기, 기대값 완화로 통과시키지 않는다. 기대값을 바꿔야 하면 사유를 변경에 적고 Codex 검토를 받는다.
- [설계] 실행 순서는 다음과 같다.
  1. 변경과 관련된 빠른 테스트.
  2. 필수 회귀(P0 전체와 해당 단계의 통합 테스트).
  3. 실 API 검증. 별도 한도 안에서, 명시적으로 켰을 때만 실행한다.

## 9. 경로 예시(제안)

테스트 러너와 파일 배치는 [미정]이다. 아래는 제안이며 확정된 구조가 아니다.

- 유닛 테스트: 대상 모듈 옆 또는 `tests/unit/<모듈>/`.
- 공용 fixture와 가짜 비밀: `tests/fixtures/`.
- 프로세스 통합: `tests/integration/`. 실 API: `tests/live/`(기본 실행에서 제외).

## 10. 미정

- 테스트 러너, 파일 배치, fixture 형식.
- 같은 실패의 판정 기준과 중단 횟수(EN-04).
- 응답을 조각으로 받는 방식의 사용 여부(PR-04의 적용 시점).
- 보호 경로 목록과 새 위치 복원 권한의 형식(PO-07, PR-07, PR-08).
