# 단계 1a 기능 작업 지시서

**상태: 구현 승인 대기.** 이 문서는 승인 뒤에 쓸 작업 배분안이다. 현재 AGENTS.md의 문서 단계 제한(제품 코드 구현, 패키지 설치, API 호출 금지)은 유효하며, 이 문서는 그 제한을 풀지 않는다. 아래 어떤 항목도 지금 수행하라는 지시가 아니다. 코드와 테스트는 작성되거나 실행된 적이 없다.

기준 문서: [아키텍처](../architecture.md), [단계별 계획](../roadmap.md), [유닛 테스트 계획](../unit-test-plan.md), [민감정보 처리](../privacy.md), [전문 페르소나](../personas.md), [개발 절차](../development-workflow.md). 이 문서와 기준 문서가 다르면 기준 문서가 우선하고 Codex가 조정한다.

표기: **[확정]** 사용자 확정 요구, **[관리]** Codex 설계 선택, **[제안]** 관리자 확정 전의 안, **[미정]** 결정 전 항목.

## 1. 목표와 범위

- [확정] 사용자가 기능 개발 지시를 요청했다. Codex가 단계 1a의 코드 작성과 개발 의존성 설치 허용 여부를 확인하고 있다.
- [관리] 목표는 API 키 없이 모의 모델로 끝까지 실행되는 최소 CLI다(roadmap 단계 1a).
- 포함: Task·Tool·Artifact·Verifier·Policy 공통 계약, 모의 모델, 도구 네 개(읽기, 목록/검색, 버전 검사 쓰기, 허용 목록 명령), 민감정보 게이트, 가림본 실행 기록, 한도와 취소, 검증기 두 종류, 코드 작업과 Git 없는 문서 작업의 프로세스 통합 검증.
- 제외: 실제 Anthropic 호출(1b), 검증 실패를 반영한 자동 재수정(단계 2), 자기 소스 수정(단계 3), GUI·IDE, 외부 발송, MCP·확장, 웹 접근, 자동 재개, 문맥 압축.

## 2. 단계 전환 조건(gate)

각 gate는 Codex만 연다. 앞 gate가 열리지 않으면 뒤 작업을 시작하지 않는다. 담당자는 스스로 gate를 넘기지 않는다.

| gate | 여는 조건 | 열리면 허용되는 것 |
| --- | --- | --- |
| G0 구현 승인 | 사용자가 문서 단계 제한을 1a의 코드 작성과 개발 의존성 설치에 한해 해제한다고 확인한 뒤, Codex가 해당 지침 변경과 작업별 요청을 확정한다 | 작업 A 착수 |
| G1 개발 환경 확정 | G0 범위 안에서 Codex가 Node 버전, 패키지 관리자, 테스트 러너(O-7)와 허용 의존성 목록을 확정한다 | 작업 A의 개발 의존성 설치. 목록 밖 의존성은 Codex 검토 필요 |
| G2 기반 인수 | 작업 A의 기반 커밋(프로젝트 설정과 계약)을 Codex가 검토해 통합한다 | 작업 B, C, D 착수 |
| G3 구현 인수 | 작업 B와 C를 Codex가 검토해 통합한다. 유닛 P0와 타입 검사 결과가 제출되어 있다 | 작업 D의 최종 검증 실행 |
| G4 채택 | 작업 D의 보고와 4절 수용 기준을 Codex가 검토한다 | 1a 완료 기록. 1b 승인은 별도 |

- 실제 API 호출은 이 지시서의 어떤 gate로도 열리지 않는다. 1b는 로컬 `ANTHROPIC_API_KEY`, 명시적 `CODARYN_MODEL`, 모델 결정(O-1), 호출 한도가 준비된 뒤 Codex가 별도 지시로 연다.
- G0 전에는 디렉터리 생성, 설정 파일 작성, 설치, 테스트 코드 작성을 하지 않는다.

## 3. 작업

코드 소유 디렉터리는 [제안]이다. Codex가 작업 요청에서 확정하기 전에는 구현 지시로 쓰지 않는다. 한 파일은 한 작업만 소유한다.

### 작업 A. 프로젝트 기반과 공통 계약

- **페르소나**: 수석 아키텍트(주), CLI 개발자(보조). 역할 1.
- **목표**: 다른 작업이 병렬로 시작할 수 있도록 프로젝트 설정과 공통 타입 계약을 먼저 고정한다.
- **구현 범위**: TypeScript 프로젝트 설정, 타입 검사와 테스트 실행 명령, 다섯 계약과 상태·권한·검증 결과의 타입, 모듈 사이의 인터페이스(model, tools, policy, privacy, verify, store), 원문 문자열과 가림 문자열의 타입 구분.
- **소유 파일 [제안]**: `package.json`, lock 파일, `tsconfig.json`, 테스트 러너 설정, `src/contracts/**`. 이 파일들은 역할 1만 수정한다.
- **선행 의존**: G0, G1.
- **완료 기준**: 타입 검사 명령이 통과한다. 계약에 Git이나 테스트 러너를 전제로 한 필드가 없다. Verifier 결과에 검사 범위와 한계 필드가 있다. 계약 변경 절차(요청 → Codex 승인 → 역할 1 수정)가 보고서에 적혀 있다.
- **제외**: 엔진·도구·정책의 동작 구현, 실제 Anthropic 어댑터의 호출 경로.
- **검토 gate**: G2.

### 작업 B. 코어, 모델, CLI, 도구 연결

- **페르소나**: CLI 개발자(주), 수석 아키텍트(보조). 역할 1.
- **목표**: 엔진이 모의 모델과 도구를 반복 호출해 작업을 한 번 수행하고 검증 결과로 상태를 정한다.
- **구현 범위**: 상태 기계와 한도 집행, 취소 처리, 모델 인터페이스와 모의 모델, 도구 네 개의 등록과 실행 연결, 검증기 두 종류(명령 종료 코드, 파일 존재·내용 규칙), 가림본 실행 기록과 작업 공간 잠금, 명령 하나짜리 CLI 어댑터. 키나 모델 설정이 없으면 실제 호출 경로를 전송 없이 거부한다.
- **소유 파일 [제안]**: `src/engine/**`, `src/model/**`, `src/tools/**`, `src/verify/**`, `src/store/**`, `src/cli/**`, `src/workflows/**`와 그 유닛 테스트.
- **선행 의존**: G2. 작업 C의 privacy·policy·workspace는 계약 인터페이스로만 호출한다.
- **완료 기준**: 유닛 P0 중 EN-01~03, EN-05~07, VF-01~03, AD-07이 통과한다. AD-01~06은 실제 어댑터를 넣는 변경과 함께 적용하며 1a에 넣지 않으면 "미도입"으로 보고한다. 모델의 완료 선언만으로 `done`이 되지 않는다.
- **제외**: 실패 후 자동 재수정, 실제 API 호출, 병렬 도구 실행, 대화형 세션.
- **검토 gate**: G3.

### 작업 C. 민감정보, 정책, 작업 공간

- **페르소나**: 보안·개인정보 검토자(주), CLI 개발자(보조). 역할 2.
- **목표**: 치환과 제한된 복원, 권한별 정책 판정, 안전한 파일 쓰기를 계약대로 구현한다.
- **구현 범위**: 등록한 문자열 비밀의 치환과 정해진 변형 일치, 토큰 발급과 검증, 구간 대응에 의한 원위치 보존, 새 위치 복원 거부, 복원 뒤 실효 인자 재검증, 치환 실패 시 전송 차단. 경로·명령·네트워크·파괴적 동작의 독립 판정. 읽은 시점 해시와 비교하는 쓰기, 원자적 교체, 줄바꿈·BOM·다중바이트 보존.
- **소유 파일 [제안]**: `src/privacy/**`, `src/policy/**`, `src/workspace/**`와 그 유닛 테스트. `src/contracts/**`는 읽기 전용이다.
- **선행 의존**: G2. 그 전에는 대기한다.
- **완료 기준**: 유닛 P0 중 PR-01~03, PR-05~11, PO-01~06, WS-01~04가 통과한다. PR-04는 조각 응답을 도입할 때 적용한다. 가짜 비밀만 사용한다. 보장하지 않는 범위(목록 밖 변형, 최선 노력 탐지, OS 격리 없음)를 보고서에 적는다.
- **제외**: 영구 금고, 숫자·표·구조 문서 형식의 치환, 이미지 가림, OS 격리 실행기, 새 위치 복원 권한의 부여 절차.
- **검토 gate**: G3.

### 작업 D. 독립 프로세스 통합 검증

- **페르소나**: 검증 엔지니어. 역할 3.
- **목표**: 구현자와 독립된 관점에서 실제 CLI 프로세스, 실제 파일시스템, 실제 자식 프로세스로 1a 수용 기준을 확인한다.
- **구현 범위**: 가짜 비밀과 모의 모델 대본, 연습용 코드·문서 작업 공간, CLI 실행과 카나리 검사 보조 도구, 4절 항목별 통합 테스트. 판정은 종료 코드, 파일 바이트, 실행 기록, 모의 모델이 받은 요청 본문으로 한다.
- **소유 파일 [제안]**: `tests/integration/**`, `tests/fixtures/**`, `tests/support/**`. 제품 `src/**`와 `package.json`은 수정하지 않는다. 구현 내부를 가져다 쓰지 않고 공개 CLI와 계약만 쓴다.
- **선행 의존**: G2에서 fixture와 테스트 작성을 시작하고, G3 뒤에 최종 실행한다. 그 전에는 대기한다.
- **완료 기준**: 4절의 각 항목이 통합 테스트 하나 이상에 대응한다. 전부 키 없이 실행된다. 제품 결함을 발견하면 고치지 않고 재현 사례와 함께 보고한다.
- **제외**: 실제 API 검증, 단계 2의 반복 검증, 자기 개발 회귀, OS 격리와 네트워크 차단의 입증.
- **검토 gate**: G4. 통합 테스트의 삭제, 건너뛰기, 기대값 완화는 Codex 검토 없이는 통합하지 않는다.

## 4. 단계 1a 수용 기준

모두 키 없이, 모의 모델로 확인한다. 근거 층을 함께 적는다.

| 번호 | 기준 | 근거 |
| --- | --- | --- |
| A1 | 임시 폴더의 작은 코드 수정 작업이 끝까지 실행된다 | 통합 |
| A2 | Git과 테스트 러너가 없는 폴더의 문서 작성 작업이 끝까지 실행된다 | 통합, VF-01 |
| A3 | 읽은 뒤 바뀐 파일에 대한 쓰기를 거절하고 사용자 바이트가 남는다 | WS-01, 통합 |
| A4 | 링크와 상위 경로를 해석한 실효 경로가 허용 루트 밖이면 거부한다 | PO-02, 통합 |
| A5 | 권한을 독립적으로 판정한다. 목록 밖 명령과 파괴적 동작을 거부한다 | PO-01, 03, 04, 06 |
| A6 | 기존 보호 구간은 원위치에서 바이트가 유지되고, 새 위치 복원은 거절된다 | PR-06~09 |
| A7 | 도구 결과는 치환한 뒤에만 기록되고 모델에 전달된다. 기록에 가짜 비밀 원문이 없다 | PR-10, 11, 통합 |
| A8 | 한도 초과는 `budget-exhausted`, 취소는 `cancelled`로 끝나고 자식 프로세스가 정리된다 | EN-03, 05, 통합 |
| A9 | 모델의 완료 선언만으로 성공이 되지 않는다. 검증 실패는 `failed`다 | EN-02, 통합 |
| A10 | 키나 모델 설정이 없으면 실제 호출 경로가 전송 없이 거부된다 | AD-07 |
| A11 | 유닛 P0(단계 1, 도입 기능 해당분)과 타입 검사가 통과한다 | 실행 결과 |
| A12 | 보고서가 "오프라인 검증 통과, 실제 API 미실행(1b 미수행)"으로 구분해 적는다 | 보고서 |

- 네트워크는 "네트워크를 쓰는 도구가 없음"까지만 확인한다. 네트워크 차단이나 OS 격리를 확인했다고 적지 않는다.
- 이 기준의 통과는 검사한 범위의 증거다. 보안이나 정확성 전체의 보장으로 표현하지 않는다.

## 5. 공통 규칙

- 시작 전에 지정 worktree에서 `git -C`로 상태, 브랜치, 최상위 경로를 확인한다. 소유 파일만 수정한다.
- 유닛 테스트는 구현보다 먼저 또는 같은 변경 단위에 넣는다. 외부 경계(모델, 시계, 난수, 명령 실행기)만 대신 넣는다.
- 커밋 작성자는 `gangdonggil <gangdonggilstudy@gmail.com>`이다. trailer와 자동 귀속 문구를 붙이지 않는다. push와 병합은 Codex가 한다.
- 키 값, 원문 대응표, 실제 비밀을 코드·fixture·기록·보고에 넣지 않는다. 키 파일을 읽지 않는다.
- 승인된 범위 안의 일상 선택은 담당자가 정하고 보고서에 남긴다. 범위 변경, 계약 변경, 목록 밖 의존성은 Codex에 올린다.

## 6. 보고 형식

작업마다 10줄 이내로 보고한다.

```
페르소나 / 작업: (예: 보안·개인정보 검토자 / 작업 C)
worktree / 브랜치:
변경 파일:
실행한 검증: 타입 검사, 유닛(P0 통과·실패·건너뜀 수), 통합
실행하지 않은 검증: 실제 API 미실행(1b 미수행), 그 밖의 항목
검사하지 않은 범위와 알려진 한계:
커밋:
관리자 판단 필요:
```

## 7. 미정

- [미정] Node 버전, 패키지 관리자, 테스트 러너, 허용 의존성 목록(O-7). G1의 전제다.
- [미정] 지원 OS(O-2)와 Windows에서 자식 프로세스 트리 종료를 검증하는 방법.
- [미정] 모의 모델 대본을 CLI 프로세스에 넣는 방법. 제품 실행 경로에 치환·정책을 우회하는 통로를 만들지 않아야 한다.
- [미정] 설정 파일과 로컬 상태 디렉터리의 위치(O-11), 실행 기록의 형식, CLI 인자와 종료 코드 규약.
- [미정] 대응표를 실행 중에만 둘지 영구 금고로 둘지, 원문 스냅샷의 보관 위치.
- [미정] 실제 Anthropic 어댑터를 1a에 넣을지 1b로 미룰지(AD-01~06의 적용 시점).
- [미정] 작업별 worktree와 브랜치 이름, 세션 배치. Codex가 작업 요청에서 정한다.
