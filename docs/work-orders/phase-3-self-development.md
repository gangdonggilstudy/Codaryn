# 단계 3 준비와 투입 편의 작업 지시

사용자가 2026-11-12에 임시 PM(w1:p3)에게 "개발 가속"이라고 지시했다. PM의 해석: 대기 중인 세션을 모두 써서 다음 단계(단계 3 자기 소스 후보 개발)의 오프라인 구현과, 실제 투입에 필요한 편의 기능을 병렬로 진행한다. 이 해석은 PM의 것이며 사용자가 다르게 뜻했다면 바로 조정한다. `docs/pm-control.json`의 범위는 PM이 바꾸지 않는다.

기준은 main `e792fb8`이다(유닛 472건 중 471 통과·1 건너뜀, 통합 273건 통과, 실제 API 미실행).

## 범위

- 포함: 보호 대상 무결성 확인, 실행본 자기 보호, 후보 작업 공간 준비 스크립트와 절차 문서, 사전 점검 명령, 도움말과 버전, 진행 표시, 이들의 유닛과 통합 검증, 모의 모델로 하는 자기 개발 예행.
- 제외: 실제 Anthropic API 호출, 무인 연속 자기 개선, 자동 병합과 자동 교체, 검증기 자체의 자기 수정, 과제 자동 선정, OS 수준 격리.
- roadmap 단계 3의 입력 조건("단계 2의 오프라인·실 API 검증을 모두 통과한 실행본")은 아직 충족되지 않았다. 이 지시는 기구를 오프라인으로 만들고 검증하는 데까지다. 실제 모델로 자기 소스를 고치는 실행은 사용자의 실제 호출 점검 뒤에 연다.

## 설계 결정 (PM)

| 번호 | 결정 | 근거 |
| --- | --- | --- |
| U-1 | 보호 대상 무결성 확인을 둔다. 실행을 시작할 때 `policy.protectedPaths` 아래 파일과 설정의 `integrity.paths`(작업 공간 밖의 검증 자료, 절대 경로)의 SHA-256 목록을 만든다. 검증기를 실행하기 직전과 직후에 다시 계산해 다르면 그 검증을 무효로 한다 | 보호 경로 정책은 파일 도구의 쓰기만 막는다. 실행된 명령이 테스트나 검증 설정을 고치는 경로를 탐지로 보완한다(architecture 7절 "보호 대상의 해시 확인") |
| U-2 | 무결성이 깨지면 상태는 `needs-input`, 이유는 `protected_changed`다. 재수정하지 않는다. 바뀐 경로 목록(가림본)을 결과와 기록에 남긴다 | roadmap 단계 3 "보호 대상이 바뀐 상태에서는 검증이 무효 처리된다". 모델이 고칠 실패가 아니다 |
| U-3 | 작업 공간이 실행 중인 CLI의 설치 위치(실행 파일이 속한 패키지 루트)와 같거나 그것을 포함하거나 그 안에 있으면 실행 전에 거부한다 | architecture 7절 "실행본은 후보 worktree만 허용 루트로 받는다. 자기 설치 위치에는 쓸 수 없다" |
| U-4 | 후보 작업 공간은 엔진이 만들지 않는다. `scripts/new-candidate.mjs`가 지정한 저장소에서 `git worktree add`로 후보 디렉터리와 브랜치를 만들고, 작업 공간 밖에 설정 파일과 task 틀을 생성한다. 기존 디렉터리나 브랜치가 있으면 아무것도 바꾸지 않고 멈춘다 | 공통 엔진은 Git을 전제로 하지 않는다. worktree는 변경 분리 수단이며 보안 경계가 아니다 |
| U-5 | 후보 채택은 자동으로 하지 않는다. 실행 결과(상태, 검증기 결과, 변경 목록, 사용량, 검사하지 않은 범위)를 사람이 읽을 수 있는 보고서로 내는 `codaryn report --workspace <디렉터리> --run <runId>`를 둔다. 병합과 교체는 PM이 한다 | roadmap 단계 3 "자동 교체는 없다" |
| U-6 | `codaryn doctor [--config ...] [--vars-file ...] [--workspace ...]`를 둔다. 네트워크에 접속하지 않고 Node 버전, 설정 파일 형식, 키 유무(값은 출력하지 않음), 모델과 한도 설정, 파일 위치 규칙, 허용 명령의 실행 파일이 PATH에서 풀리는지를 점검해 항목별로 보고한다 | 투입 전 설정 오류를 실제 호출 없이 잡는다 |
| U-7 | `codaryn --help`, `codaryn --version`, 명령별 도움말을 둔다. `npm link` 뒤 `codaryn` 명령으로 실행할 수 있게 진입 파일과 `package.json`을 정리한다 | 사용 편의 |
| U-8 | 실행 중 진행 상황을 stderr에 한 줄씩 낸다(턴 번호, 도구 이름과 허용·거부, 검증기 결과, 재수정 회차). 가림본만 쓰고, `--quiet`로 끌 수 있다. stdout은 지금처럼 JSON 한 줄이다 | 실제 모델 실행은 오래 걸리므로 진행을 볼 수 있어야 한다 |

- 유닛 P0: 무결성 목록 계산과 비교, 무결성 위반 시 상태와 비재수정, 자기 설치 위치 거부, 스크립트의 기존 대상 보존, `doctor`가 키 값을 출력하지 않음.
- 통합: 허용된 명령이 보호 파일을 고치면 `needs-input`/`protected_changed`, 작업 공간 밖 검증 자료가 바뀌어도 같음, 자기 설치 위치 거부, `report`와 `doctor` 출력, 진행 표시에 가짜 비밀이 없음.
- 자기 개발 예행: Codaryn 소스의 사본을 임시 폴더의 후보로 두고, scripted 모델이 작은 변경을 한 뒤 보호된 검증(유닛 일부)을 통과하거나 실패하는 흐름을 끝까지 돌린다. 이것은 모의 모델 예행이며 실제 자기 개발의 증거가 아니다.
- 커밋 작성자, trailer 금지, 병합 전 검토, 비밀 검사 훅은 이전과 같다. p1의 worktree는 건드리지 않는다.

## 완료 기준

1. 키 없이 타입 검사, 유닛, 통합 전체가 통과한다.
2. 보고서가 "오프라인 검증과 모의 모델 예행 통과, 실제 API 미실행, 실제 자기 개발 미수행"으로 구분해 적는다.
3. 구현자가 아닌 담당자의 교차 검토를 한 번 거친다.

| 번호 | 결정 | 대상 결함 | 담당 |
| --- | --- | --- | --- |
| V-1 | 실패 서명에서 정규화하는 숫자를 매번 바뀌는 것으로 좁힌다: 시간 단위가 붙은 수(`ms`, `s`, `µs`, `ns`), `duration`·`elapsed`·`time` 계열 키의 값, 날짜와 시각, 8자리 이상 16진수(주소). 줄·열 번호와 actual/expected 같은 값은 그대로 둔다. 실패 지점이 옮겨 가는 진전을 같은 실패로 묶지 않게 한다 | L1-1 | p5 |
