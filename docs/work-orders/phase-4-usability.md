# 사용성 개선 작업 지시

사용자가 2026-11-12에 "편의성도 확보하게 설계하고, 설계 전문가를 다시 붙여 사용성 개선을 협의해 추가 설계하고, UX 설계도 진행하고, 모두 문서화하라"고 지시했다. p6(수석 아키텍트 겸 UX 설계)이 [사용성 검토](../design/usability-review.md)와 [UX 설계](../design/ux-design.md)를 작성했고, 그 "결정 필요" 항목을 임시 PM(w1:p3)이 아래와 같이 정했다. 사용자는 추가 지시가 없으면 끝까지 연속 진행하라고 했으므로 PM이 정하고 근거를 남긴다.

기준은 main `c8c0d9b`다(유닛 722건 중 721 통과·1 건너뜀, 통합 343건 통과. 통합 전체 4회 중 1회 간헐 실패가 있어 조사 중이다. 실제 API 미실행).

## 결정 (PM)

| 번호 | 결정 | 근거 |
| --- | --- | --- |
| N-1 | 사용자 기본 설정 위치 한 곳을 자동으로 읽는다(검토 D-1의 (a)). Windows는 `%APPDATA%\Codaryn\config.json`, 그 밖은 `$XDG_CONFIG_HOME/codaryn/config.json`(없으면 `~/.config/codaryn/config.json`)이다. 우선순위는 `--config` > `CODARYN_CONFIG` > 기본 위치다. 그 위치가 작업 공간 안이면 S-1대로 거부한다. C-3("명시한 것만 읽는다")을 "명시한 것과 작업 공간 밖 고정 위치 한 곳만 읽는다"로 고친다 | 매번 `--config`를 주는 부담을 없앤다. 작업 공간 안 자동 탐색 금지라는 C-3의 목적(프로젝트가 설정을 넣지 못하게 함)은 유지된다 |
| N-2 | `codaryn init`을 둔다. 터미널에서만 묻고, 기본 설정 위치에 설정 파일을 만든다(이미 있으면 덮어쓰지 않고 멈춘다). 한도 기본값, 명령 허용 목록과 보호 경로 제안, 언어를 정한다. 키는 받지도 저장하지도 않고 환경 변수 등록 방법만 안내한다. 모델은 `models` 조회로 고르게 하고, 키가 없으면 자리표시자를 남긴다 | 설정 파일을 직접 쓰는 부담을 없앤다(검토 R-2, R-8). 키를 파일에 두지 않는 원칙(C-1)을 지킨다 |
| N-3 | 모델 자리표시자(`<...>` 모양이나 빈 값)는 `doctor`와 `run`이 설정되지 않은 것으로 본다 | 검토 R-3 |
| N-4 | 사람용 메시지를 한국어와 영어로 둔다. 선택은 `CODARYN_LANG`(ko, en) > 설정의 `language` > OS 표시 언어(한국어면 ko, 아니면 en)다. 오류 코드, JSON 필드, 종료 코드는 영어로 고정한다. 파일이나 환경의 값을 문구에 넣지 않는 규칙은 그대로다 | 검토 R-6, D-3 |
| N-5 | stdout의 JSON 한 줄 계약은 유지한다. stderr에 사람용 오류(무엇이, 어떻게 고치나, 코드)와 실행 끝 요약(상태, 검증 결과, 바뀐 파일 수, 실행 id, 다음에 할 수 있는 명령)을 낸다. `--quiet`면 생략한다. 진행 줄의 내부 코드는 사람 표현 뒤 괄호에 둔다 | 검토 R-5, R-10, R-11, UX-D3 |
| N-6 | 설정과 task 오류는 어느 필드인지, JSON 문법 오류는 줄과 열을 알려 준다. 필드 이름과 위치만 적고 값은 적지 않는다 | 검토 R-7. 기존 S-3, S-6 유지 |
| N-7 | `codaryn runs`(실행 목록)와 `--run latest`를 둔다. `revert --dry-run`은 바꾸지 않고 무엇을 되돌릴지만 보여 준다. 이미 되돌린 실행은 그렇게 표시한다 | 검토 R-10, R-12, UX-D4 |
| N-8 | 설정 파일에 `profiles`(정책·검증기·한도 묶음)를 두고 `--profile <이름>`으로 고른다. 프로필은 사용자 설정 파일에만 둘 수 있고 한도 상한 규칙(S-7)을 그대로 따른다 | 검토 A3 |
| N-9 | 한 줄 실행 `codaryn run "<목표>"`를 둔다. 현재 디렉터리를 작업 공간으로 쓰고 기본 설정과 프로필로 정책을 정한다. 현재 디렉터리가 설치 위치와 겹치면 U-3대로 거부한다. 목표 문장의 키 검사(S-8)는 그대로다 | 검토 A6 |
| N-10 | 키 파일을 자동으로 읽지 않는다. `init`과 `doctor`가 사용자 환경 변수 등록 명령을 안내한다 | 검토 D-4. 명시적 로드 원칙(C-2) 유지 |
| N-11 | 실행 중 권한을 물어 허용하는 기능은 단계 4 이후로 미룬다. 지금은 거부 사유와 허용 방법을 보여 준다 | 검토 D-5 |
| N-12 | 키와 네트워크 없이 체험하는 예시(scripted 대본과 task)를 `examples/demo/`에 둔다. 사용 문서와 README를 현재 명령(`doctor`, `report`, `models`, `init`, `runs`, `--quiet`, `npm link`)에 맞춘다 | 검토 R-1, R-9, R-13, D-6 |
| N-13 | GUI는 VS Code 확장을 먼저 만든다(UX-D1). 그 전에 엔진 쪽 어댑터 계약(실행 시작, 이벤트 구독, 취소, 결과, 보고서, 되돌리기)을 정하고 CLI도 그 계약으로 옮긴다(UX-D2). 비개발자용 독립 GUI는 설계 문서까지 만들고 형태 확정은 단계 4 뒤에 한다. 로컬 웹 서버 방식은 쓰지 않는다 | 코딩이 첫 워크플로이고 단일 프로세스 원칙(architecture 1절)을 지킨다 |

- 순서: p7이 계약(설정 필드 `language`, `profiles`, 기본 설정 위치, 새 명령의 출력 객체)을 먼저 커밋한다 → p5, p6이 병렬로 구현한다 → p7이 연결한다 → p4가 통합을 실행한다.
- 유닛 P0: 기본 설정 위치의 우선순위와 작업 공간 안 거부, `init`이 기존 파일을 덮어쓰지 않음과 키를 받지 않음, 자리표시자 모델 거부, 프로필의 한도 상한, 한 줄 실행의 설치 위치 거부, 문구에 값이 들어가지 않음(두 언어 모두), `--quiet`, `revert --dry-run`이 아무것도 바꾸지 않음.
- 커밋 작성자, trailer 금지, 병합 전 검토, 비밀 검사 훅은 이전과 같다. 실제 API는 호출하지 않는다.

## 완료 기준

1. 키 없이 타입 검사, 유닛, 통합 전체가 통과한다.
2. 처음 쓰는 사람이 `init` → `doctor` → 체험 예시 실행 → `report` → `revert`까지 문서만 보고 따라 할 수 있다(p4가 통합 사례로, p6이 재검토로 확인한다).
3. 구현자가 아닌 담당자의 교차 검토를 한 번 거친다.
